数字はすべて **2026-11-03 に本番 DB で実測**（読み取りのみ）。

- **決め手の回答は一切使わない。** `ow_join_decisions`・`ow_career_turns`（転機の3問・詳細）・旧 `join_reasons` / `join_reason_primary`・入社後レビューの表は読まない。

- 未ログインには個人カードを出さない。

## 1. 画面の構成

| | 案 |
|---|---|
| URL | **`/paths`**。起点は URL に持つ：`/paths?role=<slug>&industry=<slug>&company=<slug>`（組み合わせ可・どれか1つ以上） |
| 画面の名前 | 第一案 **「行き先」**（見出しは「同じ経歴の人の、次の一歩」）。ほかの案：「キャリアの行き先」「次に進んだ人」 |
| ナビ | ヘッダーの「ユーザー」と「記事」の間に「行き先」。スマホの下のタブは5つ埋まっているので、アバターの引き出しと `/home` の「似た経歴」の箱からリンクする |
| 未ログイン | 画面は開ける。**集計だけ**を出し、個人カードの場所には「ログインすると、この人たちの経歴が見られます」 |
| ログイン時 | 起点が URL に無ければ、本人の職歴から自動で入れる（下の2） |
| 検索エンジン | 当面は `noindex`・sitemap に載せない（中身の薄い組み合わせを知らせないため） |

### 画面の上から順に

1. **起点を選ぶ欄**：職種（大分類）・業界（大分類）・会社。今の選択はチップで出し、✕ で外せる。
2. **集計**：次に進んだ先の会社・職種（大分類）・業界（大分類）。各行は 5人以上のものだけ（3）。
3. **個人カード**（ログイン時だけ）：この起点から次に進んだ人（4）。
4. **少ないときの提案**：集計の行が1つも出ないとき、起点を一段広げるリンク（5）。

タイムラインの差し込み（「〇〇から次に進んだ人」）はそのまま残す。

## 2. 起点の選び方と、ログイン時の自動の起点

### 選べる起点

| 起点 | 例 | 備考 |
|---|---|---|
| 職種（大分類） | 営業 | `ow_roles` の親。小分類を選んでも大分類に読み替える |
| 業界（大分類） | IT・インターネット | `ow_industries` の親（`industry_id` から親をたどる） |
| 会社 | 株式会社セールスフォース・ジャパン | 掲載中・ページが開ける会社だけ選択肢に出す。検証用・エージェントは出さない |
| 職種 × 業界 | 営業 × 金融 | |
| 職種 × 会社 | 営業 × セールスフォース | 会社と業界は同時に選ばない（会社が業界を決めるので） |

組み合わせは**2つまで**（職種＋業界／職種＋会社）。3つ以上は作らない（6 の線引き）。

### ログイン時の自動の起点

- 本人の「直近の職歴」（現職があれば現職、無ければいちばん新しく始まった職歴）の **職種の大分類 × 業界の大分類** を入れる。
  - 決め方は `/home` の「似た経歴」（`getSimilarPaths`）と同じ規則。その部分（直近の職歴を選ぶ処理）を純粋な関数に切り出して両方から使う。**書き写さない。**
  - 本人の職歴は本人のものなので、会社名を伏せた職歴でも業界は使う（本人にだけ出す画面）。
- 自動で入れた起点は URL にも反映し、「あなたの直近の職歴から：営業 × IT・インターネット」と出す（✕ で外せる）。
- 職種か業界が決まらない人（職歴なし・職種なし）は、起点を空にして選ぶ欄だけを出す。
- 自動の起点で集計が出なければ、5 の広げ方を自動では当てず、提案のリンクとして出す（勝手に起点を変えない）。

## 3. 使う表とクエリ、集計の単位、5人未満の扱い

### 使う表（読み取りのみ）

| 表 | 何に使うか |
|---|---|
| `ow_experiences` | 職歴（会社・職種・開始日・`visibility_company`） |
| `ow_users` | 集計の母数（`AGGREGATE_USER_COLUMNS`）と個人カードの公開設定 |
| `ow_companies` | 業界・検証用・掲載状態 |
| `ow_roles` / `ow_industries` | 大分類 |
| `ow_talk_settings` / `ow_talk_requests` | 「話を聞く」ボタン（`lib/talk/server.ts` の `talkProfiles` 経由のみ） |

### 「次に進んだ」の定義

`lib/evidence/transitions.ts` の `buildMoves`（会社の同一性：会社 id → 正規化した社名）で、同じ人の隣り合う職歴のうち会社が変わったものを「移動」とする。提案の根拠・`/admin/evidence-gaps` と同じ関数なので数え方が割れない。

### 母数から外すもの

| 外すもの | 外し方 |
|---|---|
| 集計の母数でない人 | `isAggregatableUser`（未登録・検証用・システム・非公開・統計の利用を止めた人・`@seed.internal`） |
| 会社名を出さない職歴 | `visibility_company` が `real` 以外 |
| 検証用の会社の職歴 | `ow_companies.is_test` |
| 株式会社エージェント | 会社 id の定数（`lib/constants` に新設） |

⚠️ 外すのは**移動の単位**で行う。移動の前後どちらかが外す職歴なら、その移動を数えない。職歴を先に取り除いてから並べ直すと、「A → エージェント → B」が「A → B」という**存在しない移動**になるため。

### 集計の単位と下限

| 単位 | 下限 | 届かないとき |
|---|---|---|
| 起点全体（次に進んだ人の数） | `MIN_AGGREGATE_COUNT`（5人） | 集計を出さない。人数も出さない |
| 行き先の会社・職種・業界の**各行** | 5人 | その行を出さない。「その他」にもまとめない（まとめると引き算で分かる） |

- 行き先の職種・業界は大分類だけ。小分類・部門とは掛け合わせない。
- 1人が同じ起点から何度移っていても、各単位で1回だけ数える。
- 人数（「〇人の動きから」）は5人以上のときだけ出す。

### クエリ

- 職歴と母数を admin クライアントで 1,000行ずつ全件読む（2026-11-03 時点で職歴は数十行）。
- `unstable_cache`（300秒）。中に `no-store` のクライアントを使わない（CLAUDE.md の注意）。
- 起点での絞り込み・数えるのは純粋な関数（`lib/paths/compute.ts`）で行い、テストする。

## 4. 個人カード

| | 決めごと |
|---|---|
| 誰に見せるか | **ログイン中だけ**。未ログインの HTML にも API の応答にも、名前・id を入れない |
| 誰を出すか | 起点から次に進んだ人のうち：本人が登録済み（`isRegisteredUser`）・検証用でない・システムでない・`visibility` が `private` でない。移動の前後とも `visibility_company = real`・検証用でない会社・エージェントでない |
| 見ている人が検証用のとき | 実在の人は出さない（検証用どうしだけ。`getCompanyConnections` と同じ扱い） |
| 形 | 検索の人の行と同じ（名前・顔・「以前：会社 - 職種 → 現在：会社 - 職種」）。新しい形を作らない |
| 上限 | 1画面 24人まで |
| 「話を聞く」ボタン | **`talkButtonVisible` で判定**（`/api/talk/availability` と同じ。書き写さない）。本人が「月1件まで」「積極的に」にしている人だけに出る。相互フォローの相手には「メッセージ」 |

- ⚠️ 統計利用を止めた人（`statistics_opt_out`）は集計には数えないが、個人カードには出す（プロフィールとしては見えている人なので）。出さないほうがよければ決めていただきたい（7）。
- ⚠️ 個人カードの人数は表示しない（並べるだけ）。人数を出すと、集計の下限（5人）を回り込まれる。

## 5. 結果が少ないときに起点を一段広げる仕組み

集計の行が1つも出ないとき、次の順で「一段広げた起点」を作り、**そこで集計が出るものだけ**をリンクで出す（出ない候補は出さない）。

| 今の起点 | 一段広げた候補 |
|---|---|
| 職種 × 会社 | 職種だけ ／ 会社の業界 × 職種 |
| 職種 × 業界 | 職種だけ ／ 業界だけ |
| 会社 | 会社の業界 |
| 業界 | （これ以上広げない） |
| 職種 | （これ以上広げない） |

- 判定は純粋な関数（`widenStart`）にして、どの起点でも同じ規則になるようテストする。
- 個人カードは今の起点のまま出す（広げた起点の人を混ぜない）。

## 6. 少人数の個人が特定されないための線引き

| 線引き | 理由 |
|---|---|
| 起点の組み合わせは2つまで（職種×業界・職種×会社） | 3つ重ねると1〜2人に絞れる |
| 行き先は大分類だけ・掛け合わせない | 行き先の「会社×職種」まで出すと1人に決まる |
| 各行5人以上・「その他」にまとめない | 引き算で残りの人数が分かる |
| 起点全体が5人未満なら人数も出さない | 「4人の動き」から個人を当てられる |
| 未ログインの API は集計だけ・件数の合計を返さない | `/search` の `totalAllShown` と同じ（合計から逆算させない） |
| 期間（在籍年数・移った年）は出さない | 年と会社で個人が決まる |
| 個人カードは人数を出さない | 下限の回り込みを防ぐ |

⚠️ 企業ページ「人の流れ」と `/home` の「似た経歴」は、経歴の事実の下限を **3人**（`MIN_CAREER_FACT_COUNT`）で出している。この画面だけ **5人**にすると、同じ「〇〇を出た人の行き先」が画面によって出たり出なかったりする（7）。
