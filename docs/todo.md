## `ow_users` を副問い合わせしているポリシーを SECURITY DEFINER 関数にする（2026-08-19 記録・未着手）

**2026-08-19 に `ow_users` の anon 露出を塞いだ（`20260819100000`）が、
採ったのは「列単位 GRANT に置き替える」案。anon の SELECT 権限そのものは残っている。**

### なぜ全部剥がせなかったか

ポリシー式は**実行ユーザーの権限で評価される**（PostgreSQL: CREATE POLICY / Notes）。
`REVOKE SELECT ON ow_users FROM anon` を単純にやると、
**ポリシー式の中で `ow_users` を副問い合わせしている15表**が、anon から丸ごと403になる。

| | 実測（2026-08-19） | **実測（2026-08-28）** |
|---|---|---|
| 対象の表 | **15**（`ow_bookmarks` `ow_career_profiles` `ow_casual_meetings` `ow_company_join_requests` `ow_company_posts` `ow_conversation_messages` `ow_conversation_participants` `ow_conversations` `ow_job_applications` **`ow_jobs`** `ow_matches` `ow_mentor_reservations` `ow_notifications` `ow_user_follows` `ow_user_recommendations`） | **13** |
| ポリシー本数 | **19** | **15** |
| ポリシーが参照する `ow_users` の列 | `id`(37本) / `auth_id`(35本) / `visibility`(2本) の3つだけ | — |

⚠️ **2026-08-28 に測り直したら減っていた**（表 15→13 / ポリシー 19→15）。
   ⚠️★**数え方を間違えないこと。** 「`ow_users` を参照するポリシー」を条件なしで
      数えると **89本**出るが、それは別の指標（anon が読めない表も含む）。
      **この項目が言っているのは「anon が読める表の SELECT 系」だけ。**

```sql
select count(distinct c.relname) as 表, count(*) as ポリシー
  from pg_policy p join pg_class c on c.oid = p.polrelid
 where c.relnamespace='public'::regnamespace
   and p.polcmd in ('r','*')
   and (p.polroles = '{0}'::oid[] or 'anon'::regrole = any(p.polroles))
   and has_table_privilege('anon', c.oid, 'SELECT')
   and pg_get_expr(p.polqual, p.polrelid) ~ '\mow_users\M';
```

⚠️ とりわけ **`ow_jobs`**（`ow_jobs_company_admin_manage` が FOR ALL / PUBLIC）。
   `/companies` の「募集中 N件」「募集あり」・sitemap・LP が anon キーでここを読む。
   **403 は `?? []` で受けているので、画面は落ちず数字だけが静かに消える。**

### やること

19本のポリシーの `IN (SELECT ow_users.id FROM ow_users WHERE auth_id = auth.uid())` を、
既存の SECURITY DEFINER 関数 **`public.auth_ow_user_id()`**（anon 実行可）に置き換える。
関数は所有者権限で走るので、呼ぶ側に `ow_users` の SELECT 権限が要らなくなる。
そのうえで anon から SELECT を完全に剥がす。

⚠️ **「anon は revoke / authenticated は grant / RLS で絞る」（CLAUDE.md）に戻すのが本来の形。**
   いまは anon にも23列を配っているので、`ow_users_public_read`（`visibility='public'`）が
   anon にも効く状態が残っている。

⚠️ **やるときは、19本を1本ずつ。** ポリシーの意味が変わっていないことを
   anon / 非admin / 本人 / admin の4者で毎回測る（CLAUDE.md「最低3者で実測する」）。
   migration には `SET LOCAL ROLE anon` で15表を全部引く事後チェックを入れる
   （`20260819100000` と同じ形。**ロール切り替えはトップレベルに書く**）。

### 見つけ方（このクエリを残す）

```sql
with spaces as (
  select c.relname tbl, a.attname col,
    case when d.confrelid='auth.users'::regclass then 'auth'
         when d.confrelid='public.ow_users'::regclass then 'ow_users' end sp
  from pg_attribute a
  join pg_class c on c.oid=a.attrelid and c.relnamespace='public'::regnamespace and c.relkind='r'
  join pg_constraint d on d.conrelid=a.attrelid and d.contype='f' and a.attnum=any(d.conkey)
  where a.attnum>0 and not a.attisdropped
    and d.confrelid in ('auth.users'::regclass,'public.ow_users'::regclass)
)
select p.proname, string_agg(distinct s.sp,' + ') as 空間,
       string_agg(distinct s.tbl||'.'||s.col||'('||s.sp||')', ', ') as 内訳
from pg_proc p join spaces s
  on pg_get_functiondef(p.oid) ~ ('\m'||s.tbl||'\M')
 and pg_get_functiondef(p.oid) ~ ('\m'||s.col||'\M')
where p.pronamespace='public'::regnamespace and p.prokind='f'
group by p.proname having count(distinct s.sp) > 1;
```

## social_links に URL 形式の検証が無い（2026-08-16 記録・未着手）

**空の扱いは `optionalTextMap` で揃った（2026-08-16）が、形式は見ていない。**
実データに **`github: "a"`** のような値が入っている（`ow_users` 1行）。

`content-links` 側は **https 必須**の検証があるのに、`social_links` には無い。
**同じ「外部リンク」なのに扱いが揃っていない。**

### ★実装する前に決めること（ここが本題）

⚠️ **素直に 400 を返すと、過去の壊れた値のせいで「名前の変更すら保存できない」状態になる。**
`social_links` は `PUT /api/jobseeker/profile` に**他の項目と一緒に載る**ため、
1つでも不正な値が残っていると、そのユーザーは基本情報カードを保存できなくなる。

先に3択を決めること。

| 案 | 中身 | 引っかかる点 |
|---|---|---|
| A | **変更されたキーだけ検証する** | 保存は通る。壊れた値は**残り続ける**。「送られてこなかったキー」を保持する実装が要る（いまは丸ごと置き換え） |
| B | **保存時に壊れた値を落とす** | 自動で綺麗になるが、**利用者に断りなく消える**。「値が無いことを、ある値に置き換えない」の裏返しで、**入力したものを黙って消す**ことになる |
| C | **UI 側で該当欄に印を出して直させる** | 筋は通るが、**保存を止めるかどうかは別途決める**（止めるなら A と同じ問題が出る） |

★**壊れた行が現在1件しかないなら、先にデータを直せば「素直に400」が安全になる。**
過去の値が保存を塞ぐのは「過去の値が壊れている」から起きるので、**0件にしてから
厳格な検証を入れれば、案Aの「変更されたキーだけ検証する」実装も案Cの印も要らなくなる。**
案B（黙って落とす）は「値が無いことを、ある値に置き換えない」の裏返しなので**採らない**。

⚠️ **あわせて「UI / API / DB の CHECK をどこまで揃えるか」も決める**（CLAUDE.md の原則）。
   `social_links` は JSONB なので、DB 側で形式を縛るなら CHECK 制約の書き方から要検討。
   縛らないなら「縛らないと決めた」ことを書き残すこと。

⚠️ 参考: `content-links` の検証は `POST/PUT /api/jobseeker/content-links` にあり、
   `error` は識別子・`message` は画面用に揃えてある（2026-08-16）。文言の形はここに倣う。
