## 6. ついでに見つかったもの（直していない）

1. **目次（`JobToc`）がデスクトップでも出ている。** `className="lg:hidden"` を付けているが、インラインの `display: flex` が勝つ（ui-debugging「インライン style と CSS の優先順位」③と同じ形）。新しい構成では目次の扱いも決める必要がある。
2. **「この会社の他の募集」と「同じ職種の募集」が同じ2件を出している**（見本の求人で実測。COIN の他の2件）。「同じ職種の募集」が他社に限っていないため。指示どおり d に一本化すれば消える。
3. 「メイン業務」「関連する取材レポート」は mapJob が常に空を入れており、**一度も描かれない**。消してよい。
4. 「この職種の経験者」（`PositionMembersSection`）は廃止予定の `job_category`（自由記述）で引いている。
5. 掲載日・更新日は**サイドバーにしか無い**ので、1023px 以下では更新日が見えない（新しいヘッダーのメタ行で解消する）。

## 7. 職種が「フロントエンド」になっている理由 —— **データの値**

`ow_job_roles` にこの求人の職種が **「フロントエンド」と「ITコンサルタント」の2つ**登録されていて、`role_category_id`（派生値）と `job_category` も「フロントエンド」。表示名（`roleLabel`）は登録された1つ目の職種。**表示の対応表の誤りではない。** 企業（COIN）の登録が内容（Salesforce の実装・設計）と合っていない。
⚠️ ヒーロー（スマホ）は 2026-10-29 に「職種は出さない」と決めてある（理由がこれ）。勤務条件の「職種」とサイドバーの募集サマリーには今も出ている。
