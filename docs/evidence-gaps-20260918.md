## 1. なぜ入力UIを作らなかったか

着手前の確認で、**指示の前提（「入力する画面だけが無い」）が実装と食い違っていた**ので報告し、
方針を変えてもらった。到達経路は生きている:

```
/mypage → MypageClient → ProfileEditor → ProfileTab → CareerHistoryEditor
                                              └→ ReasonEntryButton → ExperienceReasonModal
```

⚠️ `ProfileEditor` は `/mypage` に**インラインで描かれている**（モーダルの奥ではない）。

既存UIが満たしていたもの:

| 要件 | 既存 |
|---|---|
| 職歴カードごとの入口 | `ReasonEntryButton`（未回答なら「選んだ理由を回答する（非公開）」） |
| 在籍中は入社のみ／退職済みは＋離れた理由 | 「終了年月がある在籍だけ『離れた理由』を出す」 |
| 3つまで（UI / API / DB CHECK） | `REASON_MAX=3` ＋ `careerReasons.ts` の検証 ＋ `ow_experiences_join_reasons_check` |
| 未回答が分かる | **「N件の職歴が未回答です」バナー**＋「まとめて答える」＋行のドット |
| 公開されない旨 | 「**この内容は公開されません**」＋緑バッジ |

⚠️★**同じものを2つ作らないこと**（CLAUDE.md）。不足が出たら**この既存modalを直す。**

## 2. 作ったもの

**`/admin/evidence-gaps`（「根拠の棚卸し」）** — 掲載企業ごとに1行。

| 列 | 何 | 基準 |
|---|---|---|
| 経路 | その会社へ移ってきた人（**在籍中 / 出身者**） | 3 |
| 決め手 | その会社の職歴で入社理由が答えられている件数（**在籍中 / 出身者**） | 3 |
| 話せる人 | 面談対応者の同意 ＋ **在籍中**の職歴 | 1 |
| 公開求人 | 件数 | — |
| **あと何が足りないか** | 1行（例「経路があと1件と決め手があと2件そろえば、根拠が2本立ちます」） | — |

**同じ画面に未回答者の一覧**（職歴はあるが決め手を1件も答えていない人）。
★**最終ログイン日と「設問を見ている / 見ていない」を必ず出す。**

実体は [lib/admin/evidenceGaps.ts](../src/lib/admin/evidenceGaps.ts)。

### ★在籍中と出身者を分ける理由

**経路と決め手は `ow_experiences` から積み上がるので、辞めた人の職歴でも増える。**
一方「話せる人」は `ow_company_members` ＋ **在籍中**の職歴が要る。
→ **誰に声をかけるかの判断が変わる**ので、列を分けた。

### ★`ow_transitions` を読んでいない

あれは導出テーブルで**洗い替えが手動**（2026-09-18 時点で最終 **2026-08-26**、以後 職歴が増えている）。
読むと**実態より少なく出る**ので、`ow_experiences` から**その場で隣接ペアを組む**。
⚠️ 組み方は `rebuild_ow_transitions()` と同じ規則。**片方だけ変えないこと。**

⚠️ 実際に差が出た: セールスフォースへの経路は `ow_transitions` では **1**、
   `ow_experiences` から組み直すと **2**。

## 5. 検証

| 何を | どうやって | 結果 |
|---|---|---|
| 表示（各状態） | **`/dev/preview/evidence-gaps`**（運営権限が無いと実画面を開けないため） | 4状態とも描画を確認 |
| ↑の内訳 | 立っている企業あり／実データに近い形／未回答0名／**取得失敗** | 「0社」と書かないことも確認 |
| **算出ロジック** | ★**同じ論理を SQL で独立に組んで突き合わせ** | **一致**（Salesforce 経路2・決め手1、ITOCHU 経路1） |
| 実データでの出力 | 判定を一時的に true にして本番データで描画 → 即復元 | 22社＋未回答4名、gapLine が想定どおり |
| **認可** | 非運営セッションで HTML を取得し氏名を数える | **0件** |
| ↑の対照 | guard を外す | **4件を再検出**（＝0件が本物） |
| 回答が他人に読めないか | 未ログイン／他人のセッションで PostgREST を直叩き | 下記 |

### ★回答の保護は RLS ではなく「列単位 GRANT」だった

| 何 | 未ログイン | 他人のセッション | 守っているもの |
|---|---|---|---|
| `join_reasons` / `join_reason_primary` / `leave_reasons` | **401 / 42501** | **403 / 42501** | ★**列単位 GRANT**（`authenticated` にも配っていない） |
| `select=*`（列を指定しない） | **401** | **403** | 同上（制限列が混ざるとクエリごと落ちる） |
| `ow_experience_gaps` | — | **200 / `[]`（0件）** | ★**RLS**（`ow_experience_gaps_own_manage`） |

⚠️★**「RLS で守られている」は半分だけ正しい。** 決め手・退職理由の3列は**GRANT**、
   ギャップは**RLS**。どちらも画面の実装ではないが、**直すときに見る場所が違う。**
⚠️ `ow_experience_gaps` の 0件は**意味がある**（表に19行あるので「空だから0」ではない）。

### 書き込みはしていない

この画面は**読むだけ**なので、本番への往復は発生していない。

⚠️ `npm run build` は回していない。`tsc --noEmit` / `next lint` / dev の配信HTML で代替。
