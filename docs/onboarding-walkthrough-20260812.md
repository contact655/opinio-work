## 2. 詰まった箇所の一覧

### 🔴 致命的① 新規の経歴で「入社年月」が設定できない → **経歴を追加できない**

**症状**（実測）:

```
年に 2015 を選択 → 年の値="" / 月の値=""
月に 4 を選択    → 年の値="" / 月の値=""
何度やっても空に戻る
```

入社年月は必須（`*`）なので、**保存ボタンが永久に押せない**。
「経歴を追加」からは1件も登録できない。

**原因（バグ。設計でも説明不足でもない）**
[`CareerHistoryEditor.tsx`](../src/components/profile/CareerHistoryEditor.tsx) の年/月セレクトが
互いの値を `draft.startedAt` から読む相互参照になっている。

```tsx
// 年
onChange={(e) => set("startedAt", buildYearMonth(e.target.value, parseYearMonth(draft.startedAt).month))}
// 月
onChange={(e) => set("startedAt", buildYearMonth(parseYearMonth(draft.startedAt).year, e.target.value))}

function buildYearMonth(year, month) { if (!year || !month) return ""; ... }  // ← 片方だけだと "" を返す
```

新規は `startedAt = ""` から始まるので

1. 年を選ぶ → `buildYearMonth("2015", "")` → **`""`** → `startedAt` は空のまま → セレクトが戻る
2. 月を選ぶ → `buildYearMonth("", "4")` → **`""`** → 同上

**既存の経歴を編集するときだけ動く**（`startedAt` に既に値があるため）。
退職年月（`endedAt`）も同じ構造なので、**退職年月を後から入れることもできない**。

⚠️ **今日入れた変更ではない。** `git log -S` で追うと `2d77b044`（年/月セレクト導入時）から存在する。
オンボーディングは別コンポーネントで年/月を独立した state に持っているため動く。
DB にある経歴14件はすべて migration かオンボーディング由来で、
**この画面から経歴が追加されたことは一度も無い可能性が高い。**

**招待前に必須。** これが直らないと「経歴を3社入れてください」が成立しない。

### 🟠 面倒② オンボーディング直後、最初の編集が必ず止まる

オンボーディングは現職を**勤務地なし**で作る（`prefecture = null`）。
一方 `CareerHistoryEditor` は**現職の勤務地を必須**にしている。

⇒ 登録直後の人が経歴を1文字でも直そうとすると、
**保存ボタンが disabled** になり「現職の勤務地と勤務形態を入力してください」が出る。

案内文は出るので迷子にはならないが、「触っただけなのに保存できない」体験になる。

**これは設計の帰結**（オンボーディングを軽くする / 編集では必須にする、を両立させた結果）。
選択肢は3つ:

| 案 | 内容 |
|---|---|
| A | オンボーディングにも勤務地を足す（入口が重くなる） |
| B | 編集画面の必須を「新規追加時のみ」に緩める |
| C | 現状維持（案内文があるので詰まりはしない） |

### 🟠 面倒③ 会社サジェストで「選べたのか」が分かりにくい

サジェストの行をクリックし損ねると、**入力欄はタイプした文字のままで、何も起きない。**
成功時は入力欄が「✓ OPINIOに掲載中の企業と連携します」の**選択カード**に変わるので、
成功と失敗の差ははっきりしている。ただし**失敗に気づく手がかりが「変わらないこと」しかない。**

⚠️ 失敗したまま進むと `company_id` が付かず `company_text`（自由入力）で保存される。
私は最初これを踏み、**「マスタを選んだのに company_id が null」という誤った結論を出しかけた**
（再試行したらアプリは正しく動いた。**アプリのバグではない**）。

実害は「企業ページの現役社員に出ない」「遷移の集計に繋がらない」で、
**本人には見えない**。中核価値に効く箇所なので、成功/失敗をもう少し強く出す価値がある。

### 🟡 気になる④ 「新規登録」という文言が実態と違う

マスタに無い会社を入れると **「『〇〇』を新規登録」/「OPINIOに未掲載の企業として登録」** と出る。
文言は「企業マスタにレコードを作る」ように読めるが、実際は
`ow_experiences.company_text`（自由入力）に落ちるだけで、**`ow_companies` は作られない**。

⚠️ 今日 `POST /api/biz/companies` を整えたが、**求職者は経歴入力からそこに到達しない。**
到達するのは `/biz/companies/add/new`（企業側の入口）だけ。
`source='user'`（経歴入力フローからの作成）は**入口ごとまだ存在しない**——これは設計どおり。

「登録」ではなく「この名前で記録する」等のほうが実態に近い。

## 3. 所要時間と入力負担

⚠️ **自動ブラウザでの操作なので、人間の所要時間の代わりにはならない。**
代わりに**必要な操作回数**を数えた。

| 区間 | 操作回数 |
|---|---|
| オンボーディング | 会社を打つ→候補を選ぶ→職種1クリック→年→月→送信 = **6** |
| 経歴1件（勤務地・理由・ギャップまで全部） | 会社2 + 職種2 + 年月2 + 勤務地2 + 入社理由3 + 決め手1 + ギャップ6軸 + 公開設定 + 保存 ≒ **20前後** |

**3社分だと 60 操作前後。** 理由・ギャップが全部任意で、
チップを押すだけ（自由記述なし）なのは効いている。
ただし**ギャップ6軸 × 3社 = 18回の判断**は、任意でも画面に並ぶと圧がある。

**負担の本体は入力欄の数ではなく「3社ぶん思い出すこと」。**
致命的①を直したうえで、まず1社だけ求めて残りは後から足せる形が現実的だと考える。
