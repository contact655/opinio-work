## 0. 決まったこと

| # | 論点 | 決定 |
|---|---|---|
| ① | 企業担当者の送り主は企業か個人か | **送り主はいつも「人」**。名前の横に所属企業を出す。テーマが「採用」のときだけ、会話を**企業の受信箱にも**入れる（他の担当者も見て返信できる） |

| — | プロフィールの「非公開」 | **本人の選択肢から外す**（2026-10-17。コードは用意済み・規約の改定待ち。§7） |

## 1. いまの仕組み（調査の要点。2026-10-17 実測）

| | 個人どうし（DM） | 企業から個人へ |
|---|---|---|
| 最初の1通 | `ow_conversations`（`kind='direct_message'`, `request_status='pending'`）＋1通目 | `ow_company_approaches`（別の表。理由30〜200字＋本文2000字） |
| 返信 | DB 関数 `reply_to_message_request`（返信で `accepted`、受け手を参加者に足す） | DB 関数 `reply_to_company_approach`（返信で会話を作り、1通目＝理由＋本文、2通目＝返信） |

| 返事待ちの間の追加 | 送れない（409） | 送れない |
| 上限 | 1日10件・返事待ち20件 | 返事待ち10件・同じ人へ180日・同じ理由30日（月10通は外した） |
| テーマ | **無い**（本文だけ） | **無い**（理由は自由記述） |
| 見送り | あり（相手に伝えない） | あり（相手に伝えない） |
| 通知 | ベルのみ | 求職者へはベル＋メール（30分まとめ） |

- 受信箱: `/mypage/conversations`（すべて／未返信）、`/biz/messages`（すべて／未読／返事待ち）。カジュアル面談は `/biz/meetings` で別

## 2. 作るもの（段階に分ける）

### 段階1 —— 最初の1通にテーマと一言を足す（いまの2系統のまま）

**データの持ち方は「案3」から始める**（2系統はそのまま、テーマの列と表示だけ共通）。実データが0件なので、
1つの表に寄せる移行（案1）は使われ始めてからでよい。ただし**段階2で寄せられる形**にしておく
（テーマの語彙を1か所に置き、両方の表が同じ値を持つ）。

- **テーマのマスタ**: `lib/constants/messageTopics.ts` に `{ value, label, audience }`。DB は CHECK で値を縛る（UI・API・DB の3層）
- **テーマの出し分け**（送り主と相手の関係で決める。判定は1か所の関数 `topicsFor(sender, recipient)`）

| テーマ | 出る条件 |
|---|---|
| この会社のこと（社風・事業・働き方） | 相手に**現職**がある（会社マスタに紐付くとき社名を出す。自由入力のときは「いまの会社のこと」） |
| キャリアのこと（外資系／管理職／職種チェンジ／独立 …） | 常に |
| 採用のこと（ポジションの紹介／カジュアル面談） | **送り主が企業担当者**のとき |
| この会社で働きたい・話を聞きたい | **宛先が企業**のとき（②） |

- **一言**: 100字まで（DB の CHECK でも縛る）。いまの DM 本文（2000字）とは別の項目にするか、1通目だけ100字にするかは段階1の実装で決める（§6）
- **「今回は見送ります」**: 定型文のボタン（任意）。⚠️ 相手に伝えるかは §6
- **企業からのメッセージ**: 「送った理由」の自由記述をテーマ＋一言に置き換える。⚠️ いまの「理由30字以上」「同じ理由30日」は一言100字になると意味が薄れるので見直す

### 段階2 —— 送り主を「人」にそろえ、受信箱を1つにする（①）

- 企業担当者が送る最初の1通は、テーマが「採用」なら企業の会話（`kind='company'`）として、それ以外なら個人の DM として扱う
  - ⚠️ ここで2系統の上限（個人1日10件・企業 返事待ち10件）をどう束ねるかを決める。**担当者が個人として採用の話を送れると、企業の上限が素通りになる**ので、「採用」テーマは担当者個人でも企業の枠を使う
- 受信箱の一覧に「企業から／個人から」の印（`FromTag`。定義はあるが今は表示されていない）
- このタイミングで、最初の1通を会話の中のメッセージに寄せる（案1）かを判断する

### 段階3 —— 個人から企業へ（②）

- 企業ページに「メッセージを送る」（テーマは「この会社で働きたい・話を聞きたい」「この会社のこと」）
- 宛先は企業（`kind='company'`）。担当者がいれば担当者にベル＋**メール**（いまは求職者→企業はメールが無い）
- 担当者がいない企業: 応募と同じく受け付けて運営に知らせる（`/admin/waiting-companies` に数える）。担当者が承認されると `/biz/messages` に出る
- ⚠️ いまの会話のゲート（`openReason.ts`。応募・面談・提案・興味ありのときだけ会話を開く）に、5つ目の理由「本人がメッセージを送った」を足す形になる。判定は `can_contact_without_stance`（応募と同じ）

### 段階4 —— 「採用の連絡を受け取らない」（③）

- `ow_profiles` に切り替えを1つ足す（既定は「受け取る」）。`/mypage/settings` に置く
- 「今は考えていない」の14人には、**切り替えた日の前に知らせる**（届き始める前に止められるように）
- 判定: 企業からの「採用」テーマだけを止める。いまの `can_send_scout()`（転職意欲を見る）は**候補者一覧と提案ではそのまま**使う
- ⚠️ 転職意欲の「今は考えていない」のラベルの注記（`careerPreferences.ts`）に「連絡を止める唯一の方法」とある。役割を切り替えに移すので、注記と画面の説明も同時に直す

## 3. 上限（いまの案）

| 誰が | 上限 |
|---|---|
| 一般の利用者（最初の1通） | 1日10件は残す（連打よけ）。**返事待ち20件は外す**（同じ人への連投は「返信まで送れない」で止まる） |
| 企業担当者（採用テーマ） | 企業の枠（返事待ち10件・同じ人へ180日）。個人として送っても同じ枠 |
| 全員 | 返信まで追加で送れない／ブロック／通報（`/admin/message-reports`。「対応済み」の操作はまだ無い） |

## 4. 通知

- 受け手へのベルは今のまま（`message` / `message_request` / `company_approach`）
- **メールを足す**: 最初の1通が届いたとき（受け手へ）／企業宛てのメッセージ（担当者へ）
  - ⚠️ `ow_profiles.email_*_enabled` と対にする（配信停止の切り替えを先に作る）
- 企業宛ての宛先が無い会社（実在の担当者がいるのは3社）は運営に落ちる（`recipients.ts` の③）。運営は取り次がず、担当者の登録を案内する（既存の方針）

## 5. 面談OK・スカウトの残りとの関係

- 面談OK（`ow_company_members`）は撤去済み。読み書きするコードは0件。**この機能がその代わり**になる（「この会社のこと」テーマ）
- 残すもの: `can_send_scout()`（中身は「この企業にこの人を見せてよいか」）、`ow_scout_blocks`（企業のブロック）
- カジュアル面談: 受信箱への統合は段階2の後で判断（いまは `/biz/meetings` から会話へリンク）
