# 対象業界（軸2）の語彙 — 足した理由・足さなかった理由

**作成日**: 2026-09-04（フェーズ1）
**対象**: `ow_industries`（業種マスタ）を**軸2（対象業界 = 誰に売っているか）と共有**する前提での語彙の判断。

⚠️ 件数はすべて **2026-09-04 時点の実測値**。

---

## ★最初に読むこと — 粒度を割ると突合が繋がらない

**`ow_industries` は「自社がどの業界の会社か」と「誰に売っているか」の両方で共有している。**
求職者の職歴 → 勤務先 → `ow_companies.industry_id` → `ow_industries.id` と辿った ID が、
そのまま企業側の対象業界の ID と一致することで突合が成立する。

⚠️★**したがって、片方にだけ粗い値を作ってはいけない。**
実際に「製造業（一般）」を足さなかったのはこの理由による（下記）。

同じ注意は次の3箇所にも書いてある。**どれか1つを読めば気づけるようにしてある。**

| 場所 | |
|---|---|
| `ow_industries` の TABLE COMMENT | DB を直接見る人向け |
| `ow_company_target_industries` の TABLE COMMENT | 明細を触る人向け |
| [src/lib/companies/targetIndustries.ts](../src/lib/companies/targetIndustries.ts) | コードから入る人向け |

## 足した2件

### ① 「不動産・建設」→「不動産」と「建設」に分割

| | |
|---|---|
| 前 | `realestate-construction`「不動産・建設」 |
| 後 | `realestate`「不動産」 / `construction`「建設」 |
| 旧行の扱い | **`is_active = false` の論理削除**（物理DELETEしない）。`display_order = 99` で一覧の末尾へ |

**分割してよいと判断した根拠**: 適用前に実測して、この値を使っている企業が **0社**だった。
1社でもいたら付け替え先の判断が要るので、migration の冒頭で件数を数え、
**0でなければ中止する**アサートを入れてある。

**なぜ分けたか**: 束のままだと、アンドパッド（建設向け）といい生活（不動産向け）が
**同じ値**になる。軸2は「誰に売っているか」なので、この2つは分かれていないと機能しない。

## 足さなかったもの

### ★製造業（一般）— 足さない

**理由: 軸1と軸2で同じマスタを使うため、粒度が割れると突合が繋がらない。**

求職者の出身企業は `machinery`「電機・機械」を持つ。ここで対象業界にだけ
「製造業」を作ると**別 ID になり、永久にマッチしない**。
「製造業出身の人に、製造業向け SaaS を見せる」という当初の目的がその値で達成できない。

**正しい形**は「製造業」を親、`machinery` / `materials-chemicals` / `food-beverage` を
子にした **2階層 ＋ 祖先展開**（`ow_roles` の `expandWithAncestors` と同じ）。

⚠️ ただし `ow_industries` は 2026-08-25 に**フラット20件へ作り直し、2段階セレクトも撤去**
   している（`parent_id` 列は残っているが全行 NULL）。階層に戻すのは
   **選択UI・公開ゲート・突合の3つに波及する**ので**別タスク**とする。

**当面の運用**: 製造業向け SaaS は、該当する子を**複数選ぶ**（上限3を使い切る）。
例: 工場向け SaaS → 電機・機械 ＋ 素材・化学 ＋ 食品・飲料。

### リーガル（法務・士業）— 足さない

旧 `INDUSTRY_GROUPS` の vertical には「リーガル」があったが、`ow_industries` には無い。
**該当する企業が出てきてから足す。**

### 農業・一次産業 — 足さない

同上。**該当する企業が出てきてから足す。**

## 「実データが1社以上ある値だけ作る」との関係

`ow_business_domains` の TABLE COMMENT には「実データが1社以上ある値だけを置く方針」とある。
今回はこれに抵触しない。

**あの規約は facet（絞り込みの選択肢）に0件の値を出さないための表示側の規約**であって、
マスタに値を持たないという意味ではない。軸2は**このフェーズで表示しない**ので、
選択肢としては一切出ない。

⚠️ **表示フェーズでは同じ規約が効く。** `getBusinessDomainFacets` と同じく
「掲載中の企業が1社以上ある値だけ出す」形にするなら、
**企業を入れるまで「建設」は選択肢に出ない。** それでよいと判断している
（2026-09-04 / 柴さん）。**押すと必ず0件になる選択肢を作らないため。**
