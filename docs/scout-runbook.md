# スカウト運用の手引き（開ける・止める・1通目）

⚠️★**止めたい場面は慌てている場面。** その場で調べることにならないよう、
**このファイルだけ見れば止められる**ように書いてある。**分割しないこと。**

最終更新: 2026-09-10

---

# 1. 止める ── ★軽いものから3段階

**上から順に試す。下へ行くほど影響が広い。**

## 第1手: 枠を0にする（その企業だけ・送信済みは残る）

| | |
|---|---|
| 画面 | **`/admin/scout-quotas`** |
| 操作 | 対象企業の「月間上限」を **0** にして保存 |
| 効くもの | **その企業が新しく送れなくなる**（`consume_scout_quota()` が `P0002` で弾く） |
| 効かないもの | 送信済みのスカウト（消えない）。他社（影響なし） |
| 戻し方 | 同じ画面で元の数に戻す |

⚠️ 企業側には「今月のスカウト送信枠を使い切りました」と出る。**「止められた」とは出ない。**

## 第2手: プランを `free` に戻す（その企業のスカウト機能ごと閉じる）

| | |
|---|---|
| 画面 | **`/admin/plans`** |
| 操作 | 対象企業を **`free`** にする |
| 効くもの | **スカウト送信（403）と候補者検索の両方**がその企業で閉じる |
| 効かないもの | 他社。送信済みのスカウト |
| 戻し方 | 同じ画面で `paid` に戻す |

⚠️ 候補者検索ごと閉じるので、**枠だけ止めたいなら第1手で足りる。**

## 第3手: フラグを戻す（全社共通・最後の手段）

| | |
|---|---|
| 場所 | **Vercel の環境変数** `SCOUT_SENDING_ENABLED` |
| 操作 | **値を消す**（または `true` 以外にする）→ **再デプロイ** |
| 効くもの | **全社**。`POST /api/biz/scouts` が**認証より前に 503** |
| 副作用 | ★**「準備中」の文言が全画面に戻る**（LP の FAQ・料金ページ・`/mypage/scouts`・`/biz/candidates`） |

⚠️★**反映には再デプロイが要る。** Vercel の環境変数はデプロイ単位。値を変えただけでは効かない。
⚠️★**LP は ISR（`revalidate = 300`）なので、文言は最大5分ずれる。** 送信は即座に止まる。
⚠️ 確認: `curl -s https://opinio.jp/api/health` の `commit` が新しいデプロイと一致すること。

# 2. 開ける ── ★順序を守る

**1通目が実在の求職者に届く。取り返しがつかない。**

## 手順

1. **[docs/phase0-scout-enablement-20260910.md](phase0-scout-enablement-20260910.md) の
   チェックリストを上から潰す。**
2. **開ける企業を決める。**
3. **枠を先に作る** ← ★**下の 3. を読む。作らないと実質30通で開く**
4. **プランを `paid` にする**（`/admin/plans`）
5. **Vercel に `SCOUT_SENDING_ENABLED=true` を入れて再デプロイ**
6. **`/api/health` で照合**（`commit` が一致し、**`hasResendKey` が `true`**）
7. **1通目を送る** ← ★**下の 4. を読む**

⚠️★**4と5の順序を入れ替えないこと。** フラグを先に開けると、
   **プランが `paid` の企業が既にあれば、その瞬間から送れる。**

# 3. 送信枠（`ow_scout_quotas`）

**★最初の1社は「月5通」で作る**（2026-09-10 / 柴さんの判断）。

| したいこと | やり方 |
|---|---|
| **上限を明示して作る** | `/admin/scout-quotas` で「月間上限」を保存する |
| 作らない | 何もしない。⚠️ **最初の送信時に行が自動生成され、上限は DB の既定 30** |
| **止める** | 同じ画面で **0** にする（＝第1手） |

⚠️★**行が無い状態で開けると、実質「30通」で開く。**
⚠️ **作るのは「開ける企業が決まってから」。** 今は作らない。
⚠️ **月次リセットはトリガーでも cron でもない**（`can_send_scout()` の中だけ）。
   つまり**次に誰かが送るまで先月の数字が残る**。画面は `usedThisMonth()` を通すこと。

# 4. ★1通目 ── 柴さん宛に送る

**実物のメールを目視できるのはこの1通だけ。** CC（Claude）は受信箱を持たない。

| | |
|---|---|
| 宛先 | **柴さんが受け取れるアドレス**。⚠️ **アドレスと実行のタイミングは柴さんが指示する** |
| 送信元 | ★**テスト企業ではなく、実際に最初に開ける企業** |
| CC の役割 | **準備まで。** 送信の操作はしない |

## この1通で必ず確認すること

- [ ] ★**迷惑メールフォルダに入っていないか**
      ⚠️★**過去に踏んでいる。** `opinio.co.jp` から送ったメールが相手の迷惑フォルダに入った。
         **受信トレイに無ければ、まず迷惑フォルダを見る**（「届かなかった」と判断する前に）
- [ ] **差出人の表示**（`opinio.jp <…>`）が意図どおりか
- [ ] **件名**（`【OPINIO】{企業名} からスカウトが届きました`）
- [ ] **ロゴが表示されるか**。⚠️ 画像をブロックする設定では `alt="OPINIO"` だけが出る
- [ ] **フッターの送信者情報**（株式会社Opinio / 住所 / 受信拒否の連絡先）が出ているか
- [ ] **リンク先**: 「内容を見る」→ `/mypage/scouts` ／ 「設定」→ `/mypage/settings`
- [ ] ★**スマホでの見え方**（本文の折り返し・ボタンの押しやすさ）
- [ ] **企業が書いた本文が載っていないこと**（載せないのは判断。
      [scout-email-20260910.md](scout-email-20260910.md)）
- [ ] `ow_scouts.email_status` が **`sent`** になり、`email_provider_id` が入っていること

⚠️ 迷惑メール判定が出たら、Resend 側の SPF / DKIM / DMARC の設定を確認する。
   **文面をいじる前にそちらを見ること。**

| どこ | 何が分かる |
|---|---|
| **`/admin` の要対応タスク** | 「メールが届かなかったスカウト N件」。**0件が正常** |

   ★**`skipped` は正常**（本人がメール通知を切っている）。失敗として数えない。
