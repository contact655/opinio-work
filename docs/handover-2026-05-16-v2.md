## 📚 今日の運用知見

### 1. Supabase MCP は read_only

`.mcp.json` で `read_only=true` 接続。書き込み（INSERT/UPDATE/DELETE）は MCP 経由不可。

→ **書き込みは必ず Supabase ダッシュボード SQL Editor で手動実行**

これは安全側に倒した良い設計。AI に書き込み権限を渡すリスクを回避できている。

### 2. `/companies/[id]` の本番フィルタ

`queries.ts` 391〜393行:
```typescript
if (process.env.NODE_ENV !== "development") {
  companyQuery = companyQuery.eq("is_published", true);
}
```

**本番では `is_published=true` の企業のみ詳細アクセス可能**。`is_published=false` の企業は本番では 404。

→ 動作確認 URL を選ぶ際は `is_published=true` のテスト企業を使う

### 3. 8ジャンル（ow_genres）

| display_order | name | slug |
|---|---|---|
| 1 | 外資系 | foreign-capital |
| 2 | ホリゾンタルSaaS | horizontal-saas |
| 3 | バーティカルSaaS | vertical-saas |
| 4 | メガベンチャー | mega-venture |
| 5 | シード〜シリーズA | early-stage |
| 6 | AI・LLM特化 | ai-llm |
| 7 | DX/コンサル | dx-consulting |
| 8 | IPO準備中 | ipo-ready |

### 4. ow_company_genres スキーマ

- `updated_at` カラム **なし**
- `created_at` はデフォルト `now()` あり
- `is_human_approved` カラムあり

### 5. industry 参照は 80箇所超・20ファイル以上

PR-δ（カラム廃止）の影響範囲は広い。段階リリース（PR-α→β→γ→δ）が必須。

### 6. 「ダッシュボード」のような用語選定

求職者向けキャリアプラットフォームでは、ビジネスツール的な用語を避ける。「ホーム」「マイページ」など、自然で温かい言葉を選ぶ。**Opinio の言葉遣いは「対話」「キャリア」「気軽さ」を基調に**。

### 7. 空状態 UI は教育機会

「対話一覧が空」のような空状態 UI は、プロダクトの使い方を教える絶好の機会。ガイダンス文で思想（対話起点のキャリア意思決定）を伝える。
