## 0-4. 経歴入力の負担

### ★オンボーディングは **3画面**（CLAUDE.md の「4ステップ」は古い。下の「食い違い」を参照）

`STEP = { YOU: 1, COMPANY: 2, STANCE: 3 }`（[OnboardingClient.tsx:251](src/app/onboarding/OnboardingClient.tsx)）

| # | 画面 | 聞くもの | 必須 | 「後で設定する」 |
|---|---|---|---|---|
| 1 | あなたのこと | 姓・名・せい・めい・生年月日 | **5つとも必須** | ★**出さない** |
| 2 | **直近のお勤め先** | 会社 / 部署名 / 職種 / 社内での呼び方 / 入社年月 | 任意 | ★**ここにだけ出る** |
| 3 | 転職について | `career_stance`（必須）＋ 関心のある職種（任意） | 選ぶまで進めない | 出さない |

着地は `/mypage`（`DEFAULT_AFTER_ONBOARDING`）。

### 経歴1件が保存される条件

**会社（マスタ or 自由入力）＋ 職種 ＋ 入社年月**、現職でなければ**退職年月**も。
4つ揃わなければ **1件も作らない**（`canSaveExperience`）。

⚠️ 途中まで入れた人には「◯◯が足りません」と**1回だけ**警告し、**2回目は必ず進める**
（`missingForExperience`）。何も触っていない人は止めない。

### ★離脱の痕跡は「ほぼ取れない」

| | |
|---|---|
| 下書き・部分保存 | ★**無い。** 入力値は親の React state だけで、**リロードで消える** |
| 保存の単位 | 1画面目は「次へ」で `ow_users` に保存。2画面目は「次へ」で**4つ揃ったときだけ** `ow_experiences` に保存 |
| 取れる痕跡 | ★**「完了済みなのに経歴0」だけ**。実測 **2人** |

⚠️ 以前は `onboarding_completed` を直列保存の**先頭**で立てていたため、途中で落ちた人が
「完了済み・データなし」になっていた（コード中に「実データで4人」の記録）。**2026-09-11 に順序を直済み。**
＝ いまの2人が**同じ原因とは限らない**（「後で設定する」を押した人かもしれない）。**区別する手段は無い。**

### ★抜け道の位置が問題

「後で設定する」は `step !== STEP.STANCE && step !== STEP.YOU` で出すので、
★**3画面のうち「直近のお勤め先」＝経歴を聞く画面にだけ出る。** 押すと `finish()` が走り、
オンボーディングは完了し、**経歴は保存されない**。

⚠️ これは「任意項目だから逃げ道を残す」という設計の結果で、**バグではない**。
   ただし**経歴を増やしたいなら、ここが唯一の漏れ口**。
