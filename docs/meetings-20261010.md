# 会話の日程調整（2026-10-10 / 声かけまわり 段4）

**判定と書き込みは `src/lib/meetings/server.ts` の1か所。** 定数・形式の判定は `src/lib/constants/meetings.ts`。

| 操作 | 誰が | 何が起きるか | API |
|---|---|---|---|
| 候補日を送る | 企業（会話の参加者） | 種類つきのメッセージ（`kind='meeting_slots'`）。日時3つまで・未来・15分単位（日本時間）、形式（オンライン／対面）、時間（30／60分）、同席する人（自社の有効な担当者だけ） | `POST /api/biz/conversations/[id]/meeting-slots` |
| 候補を選ぶ | 求職者（その会話の本人） | `ow_meetings`（source=slots）を作り、両方へ **.ics つきのメール**。ほかの候補は押せなくなる | `POST /api/conversations/[id]/meeting-slots/[messageId]/choose` |
| 取り消す | 企業 | 候補日（確定済みなら面談も）を取り消し。**求職者にベル（`meeting_canceled`）とメール**（確定済みなら取り消しの .ics） | `POST /api/biz/conversations/[id]/meeting-slots/[messageId]/cancel` ／ `POST /api/biz/meetings/[id]/cancel` |
| 日程調整リンクを登録 | 企業の担当者ごと | `ow_company_admins.scheduling_url`（https のみ・2048字まで）。**サーバーからは取りにいかない** | `GET/PUT /api/biz/scheduling-url` |
| 日程調整リンクを送る | 企業 | `kind='scheduling_link'`。表示は `rel="noopener noreferrer nofollow"`、ドメイン名を見せる | `POST /api/biz/conversations/[id]/scheduling-link` |
| 面談日を記録する | 企業（リンクを送った会話だけ） | `ow_meetings`（source=link）。**確定と同じ扱い**（両方へ .ics つきのメール、ホームの予定に出る） | `POST /api/biz/conversations/[id]/meetings` |

## 表

- `ow_meetings`（conversation_id / company_id / candidate_user_id / starts_at / duration_minutes / format / attendees / status / source / slots_message_id …）。
  RLS: **当事者の企業の担当者と本人だけが読める**。書くのはサーバーだけ（authenticated に INSERT/UPDATE の権限なし）。
  同じ候補日のメッセージから確定できる面談は1件だけ（部分一意索引。同時に押されても2件目は 409）。
- `ow_conversation_messages.kind` / `payload`。**text 以外と payload はサーバーだけが書ける**（トリガー `guard_message_kind_payload`）。
- migration: `20261010060000_meetings.sql`。

## 画面

- 企業の会話: 入力欄の左下に「候補日」（候補日を送る／日程調整リンクを送る）。
  面談が決まったら上部に日時と「選考管理で見る」（**決まる前は出さない**）。リンクを送った会話では「面談日が決まったら記録する」。
- 求職者の会話: 候補日のカードから1つ選ぶ。
- `/biz/meetings` の面談タブ: 「決まった面談（今日以降）」に `ow_meetings` を並べ、声かけ・提案から始まった会話には「声かけから」「提案から」。
  ⚠️ 面談申込（`ow_casual_meetings`）の行は作らない（柴さんの判断）。
- 企業ホーム: 4つ目の件数を「今日以降の面談」に差し替えた。

## 確かめたこと（検証用の企業 TYU・担当 contact+21・求職者 contact+04。データは消した）

- 弾くもの: http のリンク・2049字・過去の日時・15分単位でない・4つ・45分・他社の人を同席・別の会社の担当者が送る（404）・本人でない人が選ぶ（404）・選び直し（409）。
- 本人が選ぶ → `ow_meetings` 1件・メッセージは confirmed。メールは本人と企業へ各1通（dev のログで確認。dev は送らない）。
- RLS: 本人・その会社の担当者は読める（1行）、他の求職者・他社の担当者は 0行。本人は `ow_meetings` に書けない（42501）、メッセージの payload も書き換えられない（0行）。
- 取り消し → 面談 canceled・本人にベルの通知（宛先は本人）・メール1通。
- リンク → 記録 → 面談1件・メール2通。会話にリンクのカード（rel・ドメイン名）。
- 画面: 求職者が UI から選ぶと「（決定）」になり、ほかの候補は押せない。企業の会話・ホーム・`/biz/meetings` に出る。
- ⚠️ トリガー（kind/payload の書き換え禁止）は、RLS が先に止めるので**単体では踏めていない**（防御の二重目）。

## まだやっていないこと

- 時刻を過ぎた未確定の候補日は、自動では閉じない（選ぶ API は過ぎた日時を弾く）。
