## 🔒 確定した北極星思想

### 1. 「Opinio アカウントは1つ」

ow_users は常に「キャリアを持つ個人」を表す（1人1レコード厳守）。
企業作成は「ログイン済み個人が ow_companies を作る」操作に正規化。
「Career ≠ Permission」原則の徹底。

### 2. 軽量member (I3-α)

権限境界の思想:
- **閲覧と応募対応・面談は admin/member 両方OK**
- **編集系（企業情報、求人、メンター、記事、招待）は admin のみ**

| カテゴリ | admin | member |
|---|:---:|:---:|
| 企業情報 閲覧 | ✅ | ✅ |
| 企業情報 編集・公開 | ✅ | ❌ |
| 求人 閲覧 | ✅ | ✅ |
| 求人 作成・編集・公開・削除 | ✅ | ❌ |
| 応募管理 全操作 | ✅ | ✅ |
| カジュアル面談 全操作 | ✅ | ✅ |
| メンバー管理 招待・権限変更・除名 | ✅ | ❌ |
| メンター・記事 編集系 | ✅ | ❌ |

### 3. 「推薦はしたい、編集体験は邪魔しない」（CTA 思想）

EditorInvitation の縦3行レイアウト、薄紫トーン、編集画面ではなくダッシュボードに配置。
派手すぎず、しかし数字（3.2倍）で気持ちを動かす。

## 🚨 今日の最重要発見: B-1 権限エスカレーション脆弱性

**発見プロセス**: Part 2（権限境界）実装後、Hisato さんの「並行検証」判断により、Claude Code がコード側検証を実施 → 発見。

**脆弱性内容**: `/api/biz/members/[id]` PATCH の `permission` / `deactivate` / `reactivate` action に admin チェックなし → member が自分自身を admin に昇格できる状態。

**修正**: `705a801` で全 PATCH action に `requireAdmin` を追加、即日クローズ。

**学び**: 「**Hisato さんの UI 検証 × Claude Code のコード検証**」の両輪体制が本質的脆弱性を捕まえた事例。手動検証だけだったら見落としていた可能性が高い。

**早合点を恐れず、発覚したら即座に直す姿勢** が重要。

### 5. git log での事実確認は重要
