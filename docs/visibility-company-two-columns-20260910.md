## 4. 分かれている理由 ── ★**意図的に分けた。ただしその理由は消えている**

> visibility_company_profile (新規) = **プロフィールページ (/u/[id]) 向け**

**「別々に足されて2つになった」のではなく、面ごとに分けるつもりで足されている。**

⚠️★**しかし `/career-trajectories` は現在**存在しない**。**
   `src/app` に該当ディレクトリが無く、当時の唯一の読み手だった
   `get_public_career_steps()` も **src からの呼び出しが0件**（コメントと型定義だけ）。

⇒ **`visibility_company` は、元の用途を失ったあと6面に広がった。**

   `visibility_company_profile` だけが**1面に取り残されている。**

## 5. 統合すべきか ── **すべき**

柴さんの見立て（「伏せる動機は面によって変わらない」）を裏づける材料:

| # | |
|---|---|
| ① | ★**`/u/` のほうが露出が広い。** 候補者検索は企業アカウントだけだが、`/u/` は**ログインすれば同僚も見られる**。**弱いほうを別設定にしておく意味が無い** |
| ② | ★**候補者検索から `/u/` へ1クリックで飛べる。** 片方だけ伏せても、**同じ企業が隣の面で実名を見る** |
| ③ | 分けた根拠（キャリア軌跡ページ）が**消えている** |
| ④ | **同じ問いに2つの答えを持たせない**（`normalize_company_name` を1本にしたときと同じ） |

⚠️ 反対材料も挙げておく（弱い）:
   `/u/` は `masked` のとき**会社マスタから代替表示**（「SaaS・シリーズB・50名規模」）を作れるが、
   候補者検索は**絞り込みに使えないので「非公開企業」に倒している**（2026-09-10 の判断）。
   ⇒ **表示の作り方は面ごとに違ってよい。値を2つ持つ理由にはならない。**

# ★追い込み（2026-09-11）

## ① 引き継ぎの穴は**塞がっていなかった**

`POST /api/jobseeker/experiences` に「既存の職歴から引き継ぐ」を入れたが、
**呼び出し側3箇所すべてが `visibility_company` を明示的に送っており、分岐に到達していなかった。**

| INSERT する経路 | 数 |
|---|---|
| **DB に INSERT する箇所** | ★**1つだけ**（`POST /api/jobseeker/experiences`） |
| **その API を呼ぶ入口** | **3つ** ── オンボーディング×2 ／ 職歴エディタ×1 |
| `/admin` から作る経路 | **無い**（`/api/admin/experiences/[id]` は **PATCH のみ**） |

⚠️★**「企業ピッカーは2実装」と同じ形にはならなかった。** INSERT が1箇所に集まっているので、
   **引き継ぎのロジックも1箇所でよい。** ただし**呼び出し側が値を送ると上書きされる**ので、
   **3つの入口すべてから `visibility_company` を外す**必要があった。

### 実測（既存2件が `masked` の人が新規作成）

| 送り方 | 入った値 |
|---|---|
| **送らない**（修正後の画面） | **`masked`**（引き継いだ） |
| `"real"` を明示（**修正前の画面**） | **`real`** ← ★これが穴 |
| 既存が `hidden` / 送らない | **`hidden`** |
| **職歴0件の人**（送らない） | **`real`**（既定は変えていない） |

⚠️ 編集（PUT）は既存値をそのまま送る。**あちらは消さないこと。**

## ② `/search` に出なかった理由 ── **意図した除外。直さない**

理由は**2つ重なっていた**。どちらも意図どおり。

| # | |
|---|---|
| ① | `searchPersonHits` の母集団が **`!u.is_test`** で絞られる（`runSearch.ts:492`）。**検証用アカウントは出ない** |
| ② | `/search` に**氏名で人を引く機能が無い。** `interpretQuery` が構造化条件（職種・会社・事業領域・外資・スキル・言語）に解決できなければ0件で、「絞り込めませんでした」と出る。**氏名はどの条件にもならない** |

⇒ **`hidden` を弾く実装は空振りではない。**「セールスフォースで働いている人」のような
**会社・事業領域・外資の条件**で人を引いたときに効く（`experienceMatches`）。
**実害は無く、直す必要も無い。**

⚠️ したがって⑤は「測れなかった」ではなく **「この対象では測れない」**。
   測るなら**実ユーザーで会社条件を使う**ことになるが、そのために実ユーザーの設定を変えない。
