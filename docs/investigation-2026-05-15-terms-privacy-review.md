## Section B: 戦略整合性チェック（コードベース・LPから推定）

### B-1. 「人材紹介を出さない」との整合性

引き継ぎ書の北極星 #4「人材紹介を出さない、メンター中心」より、以下の表現が**規約・ポリシーに入ってはいけません**:

| NG 表現 | 代替案 |
|---------|--------|
| 「人材紹介」「人材紹介サービス」 | 「キャリアプラットフォーム」「求人媒体」 |
| 「転職支援」 | 「カジュアル面談・メンター相談を通じたキャリア探索」 |
| 「候補者を企業に紹介する」 | 「対話の場を提供する」 |
| 「採用が決定した場合の報酬」 | 規約には記載しない、別途契約書で |

ATS terms（第2条）は「応募者情報の管理、選考プロセスの管理」と書いており、これは Work（求人媒体）には不適切。Work の第2条はカジュアル面談・メンター制度・求人掲載を軸に書く必要があります。

### B-2. 「スカウトしない」との整合性

Opinio Work は企業から求職者へのスカウトを禁止している思想があります（Hisato 思想 #3）。規約の**禁止事項**に以下を含める必要があります:

- 採用目的での求職者への無断コンタクト
- 求職者の個人情報を採用スカウト目的で利用すること
- プラットフォーム外でのダイレクトリクルーティング

### B-3. 「成果報酬・具体額非記載」との整合性

LP 上は料金を記載しない方針が確定しています。規約（特に料金条項）の書き方:

- **OK**: 「利用料金・課金体系は当社が別途定める。詳細は個別契約書による。」
- **NG**: 具体的な成果報酬額、採用決定時の条件詳細

### B-4. 「審査しない・Wantedly 型セルフサーブ」との整合性

北極星 #1「Opinio で審査しない」。利用登録条項の書き方:

- **OK**: 「当社所定の方法で利用登録を行うものとします。」（承認制と読めない表現）
- **NG**: 「当社が審査の上、承認します」「当社の裁量により登録を拒否できます」（過度な審査権限）

ただし、**不正利用防止のための最低限の解除権は必要**。「明らかに虚偽の情報」「法令違反の利用」に限定して登録解除権を残すのがバランス。

## Section C: 実装乖離チェック（コードベース精査）

### C-1. 🔴 最重要: `/terms` と `/privacy` が 404

**現状**: フッター・ログインページから `/terms`・`/privacy` にリンクしているが、**該当ページ（route）が存在しない。**

```
src/components/Footer.tsx          → href="/privacy", href="/terms"
src/components/jobseeker/JobseekerFooter.tsx → 同上
src/app/(jobseeker)/auth/page.tsx  → <a href="/terms">, <a href="/privacy">
```

確認:
```
src/app/(jobseeker)/terms/    → 存在しない
src/app/terms/                → 存在しない
src/app/privacy/              → 存在しない
```

**リスク**: ユーザーが新規登録時に「利用規約に同意します」チェックを入れても、その規約を閲覧できない → 同意の有効性が問われる可能性あり。

**対処**: ドラフトが確定次第、`/terms` と `/privacy` ルートを最速で作成する必要があります。

### C-2. 🟡 `/biz/auth` の利用規約リンクが `href="#"` （死リンク）

```tsx
// src/app/biz/auth/page.tsx L686-687
<a href="#" style={{ color: "var(--royal)", ... }}>利用規約</a>、
<a href="#" style={{ color: "var(--royal)", ... }}>プライバシーポリシー</a>に同意します
```

企業向け登録時も同意リンクが機能していません。`/terms` と `/privacy` を作成したタイミングで `/biz/terms`（または共通 `/terms`）に修正が必要。

### C-3. 🟡 カジュアル面談申込における情報共有の同意フロー

`/companies/[id]/casual-meeting` で申込時、求職者の情報（名前、メール、相談内容）が企業担当者に共有されます。現状の実装ではこれに対する**明示的な同意取得がない**。

プライバシーポリシーに「カジュアル面談申込時に申込先企業と共有する情報」の明記が必要。

### C-4. 🟡 メンター予約時の情報フロー

`/mentors/[id]/reserve` でメンター相談予約時、求職者の情報（名前、悩み、希望日程）が 編集部→メンター に渡ります（Hisato 思想 #4「編集部の丁寧な介在」）。

この2段階の情報提供（編集部経由）の flow をプライバシーポリシーに明記する必要があります。

### C-5. 🟡 position_members（求人ページの「この職種を経験した人」）

`src/app/jobs/mockJobData.ts` に `position_members` として実在人物（メンター）の名前・経歴が求人ページに表示される仕様があります。これは **個人情報の掲載**であり、規約・同意書類での手当が必要:

- メンター登録時の同意（position_members への掲載同意を含む）
- いつでも掲載削除を申請できる旨

### C-6. 🟡 記事コンテンツ（articles）の肖像権・情報取り扱い

`src/app/(jobseeker)/articles/` の記事には、インタビュー対象者の写真・発言・経歴が掲載されます。これは「当社の取材行為」に基づくもので、プライバシーポリシーに「取材・コンテンツ制作における個人情報の利用」として明記が必要。

## Section E: 抜け漏れチェック（Opinio Work 固有のリスク）

### E-1. 🔴 未成年者の利用制限

Work は「IT 業界のキャリアを考える社会人」を対象としていますが、年齢制限の明記がありません。「18歳以上」または「職業安定法上の制限に準拠」の明記が推奨されます。

### E-2. 🔴 職業安定法・労働者派遣法との関係

求人情報を掲載する「求人媒体」は、職業安定法に基づく**特定募集情報等提供事業者**の届出対象になる可能性があります（2022年改正）。

- 求人掲載（企業 → 求職者）の情報提供を行う場合: 届出義務の可能性
- 無料で求職者に情報提供する場合も対象になりうる
- 利用規約に「当社は特定募集情報等提供事業者として適法に運営します」の文言、またはその根拠の整理が必要

**→ LegalForce に最優先で確認すべき項目です。**

### E-3. 🟡 カジュアル面談の法的性質

「カジュアル面談」は採用選考ではないという建前ですが、事実上の採用活動の端緒となります。以下の整理が必要:

- 「カジュアル面談は採用選考とは別の対話の場」である旨の明記
- 企業が面談を通じて取得した情報を採用選考以外の目的で利用することの禁止
- 面談後の企業によるフォローアップ（選考移行）のプロセス

### E-4. 🟡 メンター相談の位置づけ

メンター相談は「キャリア相談」であり、「採用活動の補助」でも「投資・法律相談」でもない点の明確化。以下の免責が必要:

- メンターの発言は個人の経験に基づく見解であり、企業・当社の保証ではない
- 相談内容の守秘義務（メンター側への守秘義務の課し方）
- メンターが相談者を勧誘・採用する行為の禁止（利益相反防止）

### E-5. 🟡 退会時のデータ処理

求職者が退会した場合:
- プロフィールデータの削除タイミング・方法
- カジュアル面談の申込記録（企業側にある情報）はどうなるか
- 取材記事・position_members への掲載は退会後も継続するか（同意書が必要）

### E-6. 🟡 Cookie / アクセス解析

Vercel Analytics が稼働している場合、Cookie バナー（同意 UI）が必要です。現状のフッターに同意取得 UI はありません。EU 向けの対応は現時点では不要かもしれませんが、「日本の個人情報保護法的にも Cookie の利用は説明義務あり」として、プライバシーポリシーに具体的な列挙が必要:

- 利用ツール名: Vercel Analytics、Supabase 等
- 取得データ: ページビュー、操作ログ等
- 利用目的: サービス改善・パフォーマンス計測

### E-7. 🟡 企業向け規約（BtoB）の別文書化

現在 `/biz/auth` に企業アカウント登録フローがあります。企業向けには別途:
- 掲載企業としての責任（求人情報の正確性保証）
- 成果報酬の定め方（別途契約書で）
- 求職者情報の利用範囲（採用活動のみ）

を規定した「企業利用規約」または「利用規約（企業向け追加条項）」が必要です。
