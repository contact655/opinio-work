# 重複防止と社内メモ（2026-10-10 / 声かけまわり 段5）

## 重複防止（本番オン）

同じ会社の誰かが180日以内に声をかけていれば、候補者検索のカードと `/u/[id]` に
「◯◯さんが◯月◯日に声かけ済み（承認待ち／やり取り中）」「再び送れる日：◯年◯月◯日」を出し、ボタンを押せない。

- 判定は送信の API の「180日は再送できない」と**同じ関数**（`getRecentlyApproached`）。送った担当者の名前・状態・再び送れる日を返すようにした。
- ⚠️ **見送られた声かけも「承認待ち」**と出す（企業には見送りを伝えない。/biz/approaches と同じ）。
- 確認: 承認待ち → カードとプロフィールに表示・ボタンなし・API は 409 ／ 見送り後も「承認待ち」 ／ 承認後「やり取り中」。

### 消す時期

| いつ | 何が起きるか |
|---|---|
| 求職者が退会したとき（`ow_users` の行が消えたとき） | 両方の表から、その人の行が消える（外部キーの on delete cascade） |
| **運営が「企業の退会」の操作をした日から30日後** | 日次の処理（`/api/cron/purge-candidate-notes`・毎日 03:30 日本時間）が、その企業の分を消す（DB 関数 `purge_withdrawn_company_candidate_notes()`。service_role だけ） |
| 担当者が全員無効になったとき | **消さない**（柴さんの判断。退会の操作が起点） |

- 「企業の退会」は `/admin/companies/[id]` の上部で記録・取り消しできる（`ow_companies.withdrawn_at`）。⚠️ いまはメモを消す起点にしか使っていない（掲載・担当者・プランは変えない）。

### 確かめたこと（dev・検証用の企業 ZAP と TYU、求職者 contact+15。データは消した）

- 求職者が API で読む → 401。1001字 → 400。他社の担当者を担当にする → 400。
- 自社の担当者は書けて読める（陽性対照）。他社（TYU）の担当者が同じ候補者を読むと 0件（ZAP のメモは入らない）。
- PostgREST 直叩き: 求職者・ZAP の担当者とも、メモ・状態の両方 42501。
- 30日後に消す: 退会の操作の当日は消えない（陽性対照）→ 31日前にずらすとメモ1件・状態1件が消えた。
