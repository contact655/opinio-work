# 1. 列挙 ── 企業に見えている範囲は**3層**

**1層目しか見ていないと「思ったより少ない」と誤る。** 実際にはリンクの先まで見える。

## 層① `/biz/candidates` の一覧の行（コードで確認）

| 出るもの | 出どころ | 備考 |
|---|---|---|
| **氏名** | `ow_users.name` | 頭文字のアバターも |
| **「転職検討中」バッジ** | `career_stance = 'active'` | ⚠️ `open` では出ない |
| メンターのバッジ | `ow_users.is_mentor` | |
| 「スカウト済み」 | `ow_scouts` | その企業が送ったぶんだけ |
| **現職の役職** | `ow_experiences.role_title` | |
| **現職の会社名** | 職歴（マスタ優先） | ★**伏せていれば「非公開企業」**（2026-09-10 に対応） |
| **職種** | `ow_roles`（子があれば子） | |
| **社会人年数** | 全職歴の最古の `started_at` から都度算出 | ⚠️ 職歴0件なら**出さない**（0年で埋めない） |
| **居住地** | `ow_users.location` | |
| **希望職種** | `ow_profile_desired_roles` | 選んだものだけ（祖先は出さない） |
| **希望勤務地** | `ow_profiles.desired_prefectures` | |

**行に付くボタン**: 「スカウトを送る」と「**プロフィール詳細**」（`/u/{id}` を別タブで開く）。

## 層② 画面には出ないが、**絞り込みには使われる**

⚠️★**ここが本人にいちばん見えにくい。** 表示されていなくても、**その条件で探されている。**

雇用形態 ／ 希望の勤務スタイル ／ 社会人年数の帯 ／ **希望年収** ／ 都道府県 ／
職種（希望職種を**祖先まで展開**して判定）。

**フリーワードの対象**: 氏名・現職の役職・**現職の会社名**・居住地・職種名・親職種名。
⚠️ 会社名を伏せた人は、**フリーワードでも当たらない**（2026-09-10 に確認）。

## 層③ `/u/{id}`（「プロフィール詳細」の先）

**候補者検索から1クリックで開ける。** ここが**いちばん広い。**

ヘッダー（氏名・肩書き・**年齢**・居住地・フォロー数・SNS・カバーとアバター）／自己紹介／
アクティビティ／**職歴**（会社・部署・役職・雇用形態・在籍期間・説明・入社理由）／学歴／
実績／受賞／資格／語学／スキル／メディア出演／記事／コンテンツリンク／在籍企業の求人。

⚠️★**年齢は `/u/{id}` には出る。** 候補者検索の一覧には**出さないし、年齢で絞り込ませない**
（労働施策総合推進法9条。`birth_date` を**取っていない**）。**層①と層③で扱いが違う。**

## ★取っていないもの

| | |
|---|---|
| **生年月日・年齢**（層①） | `select` に `birth_date` が無い。**書ける状態を残さない**ため |
| **メールアドレス** | `select` に `email` が無い |

## ⚠️★可視性の列が**2つある**。混同しないこと

| 列 | どこに効くか |
|---|---|
| **`visibility_company`** | ★**候補者検索の会社名**（層①）と `/companies` の社員一覧 |
| **`visibility_company_profile`** | ★**`/u/{id}` のタイムラインの会社名**（層③） |

⚠️ **名前が似ているうえ、本人の設定画面では別々に見える。**
   片方だけ伏せた人は、**候補者検索では「非公開企業」なのに `/u/` では実名**（またはその逆）になる。
   ⚠️ **本人に見え方を示すなら、この食い違いを必ず扱うこと。** 気づかず片方だけ設定している人がいる。

# 2. いま本人が知る手段 ── **無い**

`/mypage/settings` にあるのは「公開範囲」（`public` / `login_only` / `private`）と
「ブロック中の企業」だけ。**どれも「誰に見えるか」の粒度で、「何が見えるか」は言っていない。**

`IntentCard` は 2026-09-10 に「候補者検索に表示されていません」までは言うようになったが、
**表示されている人が、何を見られているかは分からない。**

# 3. 案（2〜3）

⚠️ 制約: **新しいカードを増やさない** ／ **既存の語彙をそのまま使う** ／ **羅列で終わらせない**。

## 案A ── `/mypage/settings` の「公開範囲」の**すぐ下**に節を1つ足す

**「公開範囲」は「誰に見えるか」、その下に「何が見えるか」を置く。**
`FormSection` を1つ足すだけで、カードは増えない（「ブロック中の企業」と同じ並び）。

出す形は**層ごとに3行**、それぞれ1文。

> **企業の候補者検索**では、お名前・現在の職種と会社名・社会人年数・お住まいの地域・
> 希望職種・希望勤務地が表示されます。
> **絞り込み**には、これに加えて希望年収・雇用形態・働き方が使われます。
> **プロフィール**（`/u/…`）は、企業が一覧から開けます。**見えるのは OPINIO に
> ログインしている人だけです。**

| 良い | 悪い |
|---|---|
| **設定を変えられる場所にある**（読んですぐ直せる） | 設定を見に来る人しか読まない |
| 公開範囲の3択と**同じ軸で並ぶ** | 実物ではなく説明文 |
| 実装が軽い | |

⚠️ ここに `visibility_company` と `visibility_company_profile` の**現在値**を出すと、
   上記の食い違いにその場で気づける。

## 案B ── 候補者検索の**行そのもの**を本人に見せる（実物のプレビュー）

`/mypage/settings` の同じ位置に、**企業が見るのと同じ1行**を自分のデータで描く。

⚠️★**成立の条件は1つだけ。** 行の描画を `CandidatesClient` から**部品として切り出し、
   候補者検索と本人のプレビューが同じ部品を使う**こと。
   **別に作ると、実物と違うものを見せることになる**（下の論点を参照）。

| 良い | 悪い |
|---|---|
| **誤解が起きない**（実物そのもの） | 部品の切り出しが要る |
| 「氏名が出る」を**文字ではなく現物で**理解できる | 層②（絞り込み）と層③（`/u/`）は行に写らないので、**結局そこは文で足す** |
| 空欄の多さがそのまま伝わり、埋める動機になる | |

## 案C ── `/u/{id}` を**本人が見たとき**に帯を出す

「このページは企業の候補者検索からも開けます」と、`/mypage` から自分のページを見たときに出す。

| 良い | 悪い |
|---|---|
| **いちばん広い層③を、実物の上で説明できる** | ★**層①（一覧の行）を説明できない**。むしろ「これが企業に見えているもの」と誤解させる |
| 追加の画面が要らない | 自分のページを見に行く人しか読まない |

⚠️ **単独では採らないほうがよい。** 案A か B の補助として。

## ★推奨

**案A を土台に、案B を後から重ねられる形にしておく。**

- 案A だけでも「知る手段が無い」は解消する。**軽く、置き場所が正しい。**
- 案B は誤解が起きない代わりに**部品の切り出しが要る**。急がなくてよい。
- 案C は**単独では誤解を生む**ので、A か B の後に。

# 4. 論点への回答

## ①「企業から見た自分」のプレビューは、実物と違うと逆効果

**そのとおり。だから差を埋める方法は1つしかない ── 同じ部品を使うこと。**
別に書き起こすと、**片方だけ直る不具合**が必ず生まれる
（この repo で繰り返している形。`?industry=` の対応表が2つあった件、
`/companies` のカードが別タブで一覧の行と挙動が割れていた件）。

⚠️ 部品を共有しないなら、**「プレビュー」と呼ばないこと。** 案A の説明文にとどめる。

⚠️ 埋まらない差が2つ残る。**プレビューを作っても文が要る。**

| 差 | なぜ行に写らないか |
|---|---|
| **層②（絞り込み）** | 画面に出ない情報なので、行を再現しても写らない |
| **層③（`/u/`）** | 行にはボタンしか無い |

## ② 置き場所 ── **設定（`/mypage/settings`）**

| | |
|---|---|
| `/mypage/settings` | ✅ **公開範囲・ブロック中の企業と同じ軸**。読んだ直後に直せる |
| `IntentCard` | ❌ あそこは「**答える／答えない**」の意思表示。**見え方の説明を混ぜると問いがぼやける** |

⚠️ `IntentCard` は 2026-09-10 に「候補者検索に表示されていません」を出したばかりで、
   **1枚で2つのことを言わせない**（あのカードの注記にも「一度に2つ言わない」と書いてある）。
   ⚠️ ただし**設定への導線**は要る。IntentCard から `/mypage/settings` へ1本。

## ③ `career_stance` 未設定の人を同じ画面で扱えるか ── **扱える。むしろそこが要**

**同じ節で、状態によって書き分ける。**

| 状態 | 出すもの |
|---|---|
| 未設定 | 「**いまは候補者検索に表示されていません。**答えると、次のものが表示されます」＋一覧 |
| `no_contact` | 「**あなたの選択で表示されていません。**表示される場合は次のものが出ます」＋一覧 |
| それ以外 | 「**いま表示されています。**次のものが見えています」＋一覧 |

⚠️★**未設定の人にも中身を見せること。** 隠すと「答えたら何が起きるか分からないまま答える」
   ことになる。**答える前に知りたいのがまさにこれ。**
⚠️ 文言は `IntentCard` と**同じ言い回しに揃える**（「企業の候補者検索に表示されていません」）。
   ⚠️ **2箇所で違う言い方をしない。** 定数にするかどうかは実装時に決める。
