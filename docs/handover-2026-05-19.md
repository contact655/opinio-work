## 障害記録：ow_experiences.why 本番500（2026-05-19 / クローズ済み）

### 障害
本番 opinio.jp で職歴の保存・取得が全面的に500エラー。
レスポンス: {"error":"column ow_experiences.why does not exist"}
影響範囲：/profile/edit の職歴 新規作成・取得・編集すべて。
ユーザーには「職歴はまだ登録されていません」「追加に失敗しました」と表示されていた。

### 原因
ow_experiences.why カラムを削除する migration が DB に先行適用されていた一方、
コード側は why を INSERT/SELECT/UPDATE/表示で参照したままだった。
DBとコードの不整合により、職歴系APIが500で全面停止。
本質：カラム削除を expand-contract の逆順で実施したことによる本番障害。

### 対応（前進復旧：DBを正としコードをwhy非依存に修正）
- STEP 1 棚卸し：grep -rn "\bwhy\b" src/ で全why参照を分類。
  「対象7ファイル」「除外2ファイル（記事スラッグ誤マッチ）」以外の
  実フィールドwhy = 0件 であることを確認。
- 除外（変更せず）：src/app/articles/mockArticleData.ts /
  src/app/mypage/mockMypageData.ts（"layerx-nakamura-why-mentor" 誤マッチ）
- 修正：対象7ファイルから why を完全除去
  - src/app/api/jobseeker/experiences/route.ts（SELECT/レスポンス/POST payload）
  - src/app/api/jobseeker/experiences/[id]/route.ts（更新 payload）

### 再発防止ルール（重要・恒久ルール化）
カラム削除（column drop）は必ず expand-contract を順守する：
  ① コードから当該カラムの参照を完全除去 → デプロイ
  ② 本番が ● Ready であることを commit hash で確認
  ③ ②の確認後に、後追いで migration による column drop を実施
**逆順（DB先行drop → コード後追い）は本番全面停止を招くため厳禁。**
DB変更とコード変更を別デプロイに分ける場合は特にこの順序を厳守すること。
このルールは既存の運用ルール（npm run build → git push origin main →
Vercel ● Ready 確認）に並ぶ恒久ルールとして扱う。
