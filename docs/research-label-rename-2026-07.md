### 機能として残すべき文言 vs 薄める/消す文言

| カテゴリ | 文言 | 理由 |
|---------|------|------|
| **残す（機能）** | `面談を申し込む →`（E変更後） | `/companies/[id]/casual-meeting` へのリンク。面談フロー本体 |
| **残す（機能）** | `カジュアル面談（無料）`（G） | 機能の説明として必要 |
| **薄める→変更** | `話を聞く →`（E） | 「話す」訴求が強い。「面談を申し込む」の方が中立 |
| **削除推奨** | `直接話せる · 無料`（C） | ヘッダーバンドのサブバッジ。訴求が強すぎる |
| **削除推奨** | TalkBadge「話せます」（D） | 名前横のオレンジバッジ。不要になる |
| **変更** | 注記M（913行） | 「話せる人」という語を抜く |

## 6. 実装の分割案

### 案A: 1コミットで全部（推奨）

変更量が少ないので（/people ~10箇所、/feed ~2箇所）1コミットにまとめた方がシンプル。

```

- src/app/(jobseeker)/feed/FeedClient.tsx  （h1 1箇所）
- src/app/(jobseeker)/feed/page.tsx  （metadata 1箇所）
```

### 案B: 2コミット（ナビ先行・ページ後）

```
Commit 1: ナビ変更のみ（JobseekerHeader + MobileBottomNav）
Commit 2: ページ内文言変更（PeopleListClient + FeedClient + feed/page.tsx）
```

変更量から案Aで十分だが、「ナビだけ先に確認したい」場合は案Bも有効。
