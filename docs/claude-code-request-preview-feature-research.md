# 依頼: プレビュー機能の現状調査レポート作成

## 依頼の背景

Opinio Work のプレビュー機能を本格実装し、他の編集画面に横展開する予定。
ただし、現状の実装範囲が不明確なため、**先に現状調査レポートを作成** してほしい。

実装には着手しない。**調査のみ**。

調査結果をもとに、Opus 4.7 with Hisato で仕様書を作成 → その後 Claude Code で実装、という段取り。

## 出力先

`docs/research-preview-feature-current-state.md`

## 調査項目

### 1. 既存のプレビュー機能の実装箇所

#### 1-1. コード検索
以下のキーワードで `src/` 配下を grep し、関連ファイルをリストアップ:

```bash
grep -rn "preview" src/ --include="*.tsx" --include="*.ts"
grep -rn "プレビュー" src/ --include="*.tsx" --include="*.ts"
grep -rn "draft_data" src/ --include="*.tsx" --include="*.ts"
```

#### 1-2. ルート確認
- `src/app/` 配下でプレビュー用のルートが存在するか確認
- 例: `/preview/...`, `/companies/[id]/preview`, `?preview=true` のクエリパラメータ方式 等
- 候補をすべてリストアップ

#### 1-3. 各実装箇所の動作仕様
各プレビュー機能について、以下を整理:

| 項目 | 内容 |
|---|---|
| 実装ファイル | パスを明記 |
| 起動方法 | ボタン？URL直打ち？ |
| データソース | `draft_data` から？本番テーブルから？ |
| 表示先 | モーダル？新タブ？同一ページ？ |
| 動作状態 | 動く / 動かない / 部分的に動く |
| 未実装の部分 | あれば具体的に |

### 2. 編集画面の棚卸し

Opinio Work には複数の編集画面があるはず。すべて棚卸ししてリスト化:

候補（思いつく範囲、調査で増減してOK）:
- 企業情報編集（`/companies/[id]/edit` 等）
- 求人編集（`/jobs/[id]/edit` 等）
- ユーザープロフィール編集
- メンバー（採用担当者）編集
- 記事編集（あれば）
- その他

各編集画面について:

| 編集画面 | パス | プレビュー機能の有無 | 下書き保存（draft_data）対応の有無 |
|---|---|---|---|
| 例: 企業情報編集 | `/companies/[id]/edit` | ✅ あり（動作完全） | ✅ あり |

### 3. データモデル調査

#### 3-1. `draft_data` カラムの実態
- `ow_companies.draft_data` の現在の使われ方
- 他のテーブルにも `draft_data` または相当するカラムがあるか
- スキーマ確認（`supabase/migrations/` 配下を確認）

#### 3-2. 「公開」フローとの関係
- 5/13実装の「draft_data → 本番展開」フローを再確認
- 「変更を公開する」ボタンのコード所在
- 公開時のデータコピー処理の場所

### 4. UI 観点の調査

#### 4-1. 現状のプレビューUIパターン
既存実装の UI が、以下のどのパターンに該当するか:

- **パターンA: 同一ページ内タブ切替**（編集タブ ⇔ プレビュータブ）
- **パターンB: モーダル/ダイアログ**（編集画面の上にプレビューを重ねる）
- **パターンC: 新タブ・別URL**（プレビュー専用ページを別タブで開く）
- **パターンD: 分割ビュー**（左に編集、右にリアルタイムプレビュー）
- **パターンE: そもそもプレビューがない**

#### 4-2. 公開後ページとの整合
プレビュー時の表示が、実際の公開後ページ（`/companies/[id]` 等）と
**ピクセル一致しているか / 差分があるか** を確認。

差分がある場合、どこに差分があるかリスト化。

### 5. 残課題・技術的負債の発見

調査中に気づいた以下の点をすべて報告:

- 想定外の実装（仕様書にない機能、または逆に欠けている機能）
- データの癖（`employee_count` のフォーマット混在のような落とし穴）
- 横展開時に問題になりそうな箇所
- リファクタリング候補

## 重要な注意事項

1. **実装には一切着手しない**。コード変更・コミット・push すべて禁止。
2. 純粋な調査・分析のみ。
3. 不明点があれば「不明」と明記、推測で埋めない。
4. 想定と実態の差分は具体的に（「だいたい合ってる」ではなく「ここが違う」）。
5. レポートは Markdown で、図表（表）を積極的に使う。
6. 完了後、レポートのパスを報告。
