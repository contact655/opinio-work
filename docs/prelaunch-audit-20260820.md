### ① 中断だけでは止まらない（最も重い）

`@supabase/auth-js` は **fetch の失敗をすべて `AuthRetryableFetchError` に変換**する。
**AbortError もそこに入る**ため、中断すると再試行ループが
`AUTO_REFRESH_TICK_DURATION_MS = 30秒` まで回る。
**上限を掛けたつもりが、掛けたせいで約28秒かかっていた。**
Vercel の middleware 上限は25秒なので**確実に 504**。

実測（本番・期限切れトークンで公開ページに同時10本）: **6本が 504**（26秒）。

→ 中断はソケットを閉じるために残し、**返る時刻は `Promise.race` で決める**。

### ② 429 が「未ログイン」に化ける

`NETWORK_ERROR_CODES` は 500〜530 だけで、**429 は再試行対象外**。
即エラー → `user = null` → middleware が `/auth` へ飛ばす。

本番ログ 2026-08-19 18:36:30〜34 に、middleware 由来の refresh が
**5秒間に21本すべて 429**。

⚠️ **GoTrue 自体は同時リフレッシュに強い**（同じトークンで同時20本 → 全部 200・0.8秒）。
   競合ではなく **IP 単位の上限**が効いている。

→ 一時的な失敗（429 / 5xx / 上限超過）だけ **250ms 後に1回だけ引き直す**。
