# 企業からの「メッセージリクエスト」— 規約・プライバシーポリシーで書き換えが要る箇所（2026-10-09）

> ★**2026-10-11 に名前を「声かけ」から「メッセージリクエスト」に改めた**（柴さんの指示）。
> 規約・プライバシーポリシーでは、個人どうしの DM の「メッセージリクエスト」と区別するため、
> **「メッセージリクエスト（企業から）」**と書く（初出で定義し、以降は文脈で明らかなら「メッセージリクエスト」）。
> 企業側の状態の言い方も「承認」ではなく「**受け入れ**」（返事待ち・受け入れられた）に揃えた
> （[approach-wording-20261011.md](approach-wording-20261011.md)）。この文書の「書き換え先」もこの言葉で書き直してある。

**今回は規約を変えていない**（柴さんの判断）。スカウトの記述（計52件）の改定と同じタイミングで、
次の箇所を「メッセージリクエスト」の実態に合わせて書き換える。

## メッセージリクエストの実態（書き換えの前提）

| 項目 | 実装 |
|---|---|
| 受け取るか | `ow_profiles.accept_company_approaches`（転職意欲とは**別の設定**）。既存の利用者は「受け取らない」から始まり、/mypage で一度だけ確認する。新規はオンボーディングで選ぶ |
| 届く相手 | `can_send_scout()` が true（在籍した会社・グループ会社・ブロック・転職勧奨禁止を除く）かつ 転職意欲が「今は考えていない」・未設定でない かつ 受け取ると選んだ人 |
| 受け入れる前に見えるもの | 企業名・担当者の名前・理由・最初の1通の本文（全文） |
| 受け入れると | 企業との会話が開き、やり取りを始められる |
| 見送ると | **企業には伝わらない**（企業の画面は「返事待ち」のまま） |
| 期限 | 返事待ちのまま30日で求職者の一覧から消える |
| 上限 | 1社あたり月10件・返事待ち10件・同じ人へは180日再送不可・同じ理由は30日使い回し不可 |
| 料金 | 有料の機能（`companyApproach`）。ベータ期間中は無料プランでも使える |

## 送る担当者・同席する人は、操作している人と is_test が同じ担当者だけ（2026-10-10 / 柴さんの指示）
