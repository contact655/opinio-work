## 1. いまの流れ

### 1-1. 押してから会話が始まるまで（合う会社の下段「すべての会社を合う順に」）

入口は `src/lib/forYou/react.ts` の `reactForYou()` だけ（API `/api/jobseeker/for-you/[companyId]` はこれを呼ぶ）。

| 順 | 何が起きるか | 実体 |
|---|---|---|
| ① 押す | 本人が「話を聞いてみたい」（記録上は `interested`）。担当者がいる企業ではひとこと（200字まで）を書ける | 画面 `ForYouSection.tsx` |
| ② 確かめる | 押した時点の順位とシグナルを**サーバーで計算し直す**（`buildForYou`）。一覧に出ていない会社（ブロック中・在籍中・掲載外）は404 | `react.ts` |
| ③ 記録 | `ow_for_you_reactions` を upsert（`interested_at` は一度入ったら消さない） | 同上 |
| ④-a 担当者がいない | 運営へ1件ずつメール（件名【興味あり・担当者未登録】）。`ops_notified_at` を入れる | `notifyOps.ts` ／ テンプレート `forYouInterestOpsTemplate` |
| ④-b 担当者がいる | **その場で会話を作る**（`openCompanyConversation(source:'for_you')`。判定は応募と同じ `can_contact_without_stance()`） | `openReason.ts` |
| ⑤ 会話の中身 | 案内の行「〇〇さんが…話を聞いてみたいと答えました」（`kind='proposal_intro'`）＋ひとことを本人の発言として1通目 | `react.ts` |
| ⑥ 企業へ通知 | `notifyCompanyProposalRaised` が担当者（無ければ運営）にメール。**本文に候補者の氏名が入る** | `proposalNotification.ts` |

「担当者がいる」の判定は「見ている人と `is_test` が一致する有効な担当者がいる」（`filterCompaniesWithRespondingStaff`）。検証用と実在は混ざらない。

### 1-2. 提案（上段・OPINIO が作る）

`/admin/proposals` で運営が作る → 求職者に届く → 「話を聞いてみたい」（`respond.ts` の `saveCandidateResponse`）→ `introduceProposal()` が**その場で会話を作る**（企業は答えない）。
2026-10-11 の一時期だけ「企業が14日以内に会うか決める」（review）があり、同日に外した。**列と `ow_company_proposal_settings` は残っている。**

### 1-3. 担当者がいない場合に運営へ送っているメール

| 項目 | 中身 |
|---|---|
| 宛先 | `ADMIN_EMAIL`（運営） |
| 件名 | `【興味あり・担当者未登録】{企業名}`（検証用アカウントなら先頭に【検証】） |
| 本文 | 押した人の**氏名**、企業名、押した時点の順位、表示した理由、「運営は受け取るが取り次がない（2026-09-15 の取り決め）」、運営画面の企業ページへのリンク |

⚠️ 「取り次がない」は 2026-09-15 の決まり。今回の「運営が営業に使う」はこの決まりの変更にあたる（§論点）。

### 1-4. 押された記録・取り消し・同意の記録

| 表 | 列 | 件数（2026-10-27） |
|---|---|---|
| `ow_for_you_reactions` | `reaction` / `interested_at` / `ops_notified_at` / `conversation_id` / `rank_at` / `signals` | 2行（interested 0） |
| `ow_proposals` | `candidate_response` / `candidate_note` / `candidate_responded_at` / `introduced_at` / `conversation_id` ／（未使用）`company_response` / `company_respond_by` / `company_seen_at` / `delivery_mode` | 0行 |

- **取り消し**: 合う会社は「会話がまだ開いていないとき（担当者のいない会社）」だけ取り消せる（`undoInterest`）。会話が開いたら取り消せない。提案は答えたら変えられない（`candidate_pending` のときだけ答えられる）。
- **合意の記録**: 押した時刻は残る。**どの文言（版）を見て押したか、何が渡ることに同意したかは残していない。** 企業側の意思表示の記録は今は無い（列はあるが未使用）。
- 合う会社のひとことは**保存先が無い**（担当者がいる企業では会話の1通目になるだけ。担当者のいない企業では受け取らない）。提案には `candidate_note` がある。

## 2. 企業に届ける候補者カード

### 2-1. 個人が特定されうる組み合わせ（実在の利用者で実測）

母数は `isAggregatableUser` と同じ条件（本人が登録・検証用でない・システムでない・非公開でない・統計利用を止めていない・seed でない）。

| 組み合わせ | 組の数 | 1人だけの組 | 5人未満の組 |
|---|---|---|---|
| 会社 × 職種の大分類 | 32 | **30** | — |
| 業界の大分類 × 職種の大分類 | 18 | **12** | **17** |
| 学校（一覧から選んだもの） | 7 | **6** | — |

実在の利用者 43人・職歴がある人 31人・職歴 52件（うち社名を手で打った 7件）。

- **社名を出すと、ほぼ全員がその場で特定できる。** 業界・職種の大分類に丸めても、OPINIO の中では多くが1人。
- ★**`/biz/candidates` との突き合わせ。** 「転職について」で受け取る意思を示した人は、企業の候補者一覧に**実名**で出ている（5-1 の1行目）。匿名カードの特徴（業界・職種・年数・地域）で一覧を絞れば、同じ人が見つかる。**カードをいくら丸めても、この一覧がある限り匿名にはならない。**
  → 対策の候補（§論点 3）: ①その企業の候補者一覧に出ている人のカードは、合意まで一覧から外す ②カードの項目を一覧で絞れない粒度にする（業界と職種だけ・年数の帯を粗く）③「匿名」とは言わず「氏名と連絡先は合意まで渡しません」と言う
- 社外の知識でも特定されうる：前職の企業がその会社自身・競合・取引先なら、「業界×職種×年数」で思い当たることがある。

### 2-2. 出す項目／出さない項目（案）

| 区分 | 項目 | 匿名の段階 | 理由 |
|---|---|---|---|
| 経歴 | 経歴の流れ（業界の大分類 → 業界の大分類） | **出す** | 「人の流れ」と同じ粒度 |
| 経歴 | 職種の大分類（現職・前職） | **出す** | 同上 |
| 経歴 | 社会人年数 | **帯で出す**（〜3年／3〜6年／6〜10年／10年〜） | 年単位でも絞れる |
| 経歴 | 社名（現職・前職すべて） | **出さない** | 30/32 が1人 |
| 経歴 | 部署名・社内での呼び方・業務内容・入社理由の記述 | **出さない** | 自由記述は特定につながる |
| 経歴 | 在籍期間の年月 | **出さない**（「約3年」程度も避ける案） | 年月は特定の決め手になる |
| 本人 | 氏名・写真・連絡先・URL・SNS | **出さない** | 前提の線引き |
| 本人 | 年齢・生年 | **出さない**（帯も出さない案） | 年代で絞れる。年齢で選ばせない方針（労働施策総合推進法9条）とも揃える |
| 本人 | 性別 | **出さない** | 均等法5条の方針 |
| 本人 | お住まい | **出さない**（「首都圏」程度にするかは論点） | 都道府県で絞れる |
| 本人 | 学歴 | **出さない** | 6/7 が1人 |
| 本人 | 希望職種（大分類） | **出す** | 企業が会うかを決める材料 |
| 本人 | 本人のひとこと | **出す（任意・本人が書いたものだけ）** | 押すときに書く。特定できることを書かないよう画面で注意する |
| 回答 | 転機の3問（決め手・Q2・Q3）・任意の段 | **出さない（個人単位では一切）** | 前提の線引き |
| 回答 | 年収（職歴ごと） | **出さない** | 本人の編集画面にしか出さない決まり |
| 根拠 | OPINIO が付ける根拠の文 | **出す（経歴由来だけ）** | 下の 2-4 |

### 2-3. 本人のひとこと

- 合う会社には保存先が無い（§1-4）。**押すときに任意で書けて、合意まで OPINIO が預かる**形が要る（`ow_for_you_reactions` に列を足すか、提案と同じ `candidate_note` に揃える）。
- 上限は提案と同じ 200字（`PROPOSAL_NOTE_MAX`）。画面に「名前・社名・連絡先は書かないでください。会社が『会いたい』と答えるまで、あなたが誰かは伝わりません」と出す案。
- ★書かれた内容で特定できてしまうこと（「◯◯社で△△をしていました」）は止めきれない。運営が目で見るか、社名らしい語を検知するかは論点。

### 2-4. 根拠の文言

| 根拠 | 由来 | 出せるか |
|---|---|---|
| 「御社と同じ事業領域の会社で経験があります」 | 本人の職歴（会社の事業領域） | **出せる**（社名は出さない） |
| 「御社の求人の職種（営業）の経験があります」 | 本人の職歴の職種 × 公開求人 | **出せる** |
| 「御社の社員・OB と、前職の業界と職種の流れが近い人です」 | 経歴の事実（人の流れ） | **出せる**（ただし御社側の社員が少ないと、比べた相手が誰か分かる。社員3人以上のときだけ） |
| 「決め手が御社の社員と同じ」「1年後に合っていた」 | 転機の回答 | **出さない**（回答由来。前提の線引き） |
| 「この会社を合う順◯位で見ていました」 | OPINIO の並び | 出さない案（順位は本人の他の行動を推測させる） |

いまの合う会社の理由文（`weights.ts` の `reasonText`）は求職者向けの人称（「あなたの経験職種…」「前職と同じ…」）。**企業向けは別に組む**（保存は事実だけ、文は読む側で組む。CLAUDE.md「スナップショットに入れてよいのは事実だけ」）。

## 3. 双方合意と開示

### 3-1. 流れ（案）

1. 求職者が「話を聞いてみたい」（任意のひとこと）→ OPINIO が受け付ける（企業には**まだ何も**届かない／担当者がいる企業にだけ匿名カードが届く）
2. 企業が匿名カードを見て「会いたい」／「今回は見送る」
3. 「会いたい」→ その場で開示（氏名・公開プロフィール）＋会話を作る（`openCompanyConversation` の1か所）＋双方に通知
4. 「見送る」・期限切れ → 企業にはそれ以上何も渡らない。求職者には伝え方を揃えて知らせる（下）

使える既存のもの: `ow_proposals` の `company_response` / `company_respond_by` / `company_seen_at`、`ow_company_proposal_settings`、会話の案内の行（`kind='proposal_intro'`）、見送り理由の表（`ow_proposal_declines`・運営だけ読める）。

### 3-2. 期限と伝え方

- 期限は **7日**（指示の例）。2026-10-11 の review は14日だった。
- ★**見送りと期限切れを、求職者には区別しない**（区別すると「見送られた」と分かって傷つける）。文言の案:
  - 「今回は、話す機会につながりませんでした。あなたの経歴に合う会社は、ほかにもあります。」＋「あなたに合う会社を見る」
  - 期限前に本人が取り消した場合は何も送らない
- 企業側には見送った候補者を後から見せない（終了のタブにも出さない。2026-10-11 の `companyTabOf` と同じ考え）。

### 3-3. 置き場所と通知

| | 案 |
|---|---|
| 企業の画面 | `/biz/messages` に「OPINIOからの紹介」のタブ（2026-10-11 に `/biz/proposals` を `/biz/messages` に統合済み。語は「紹介」で揃える決まり） |
| 企業への通知（メール） | `getCompanyNotificationTarget`（担当者 → 無ければ運営）。★**匿名の段階では氏名を入れない**（いまの `proposalRaisedCompanyTemplate` は氏名を入れている） |
| 企業への通知（Slack） | 既存の `notifyCompanySlack`（30分まとめ・`include_candidate_name` の設定あり）。種別に「紹介」を足す。★匿名の段階では設定に関係なく名前を出さない |
| 求職者への通知 | ベル（`ow_notifications`。種別を足したら `survives()` の case も足す）＋メール |

| 列 | 中身 |

### 4-3. 柴さんが企業へ連絡するときの文面の材料

- 「OPINIO で、御社の話を聞いてみたいという方がいます（人数は帯）」
- 「経歴の傾向：営業 × IT・インターネット が中心」（3人以上の項目だけ）
- 「担当者を登録いただくと、匿名の経歴と本人のひとことをご覧いただけ、会いたい方とだけ氏名を交換できます」
- ★出さないもの：氏名・社名・ひとことの本文（本人が「この会社に」と書いたものでも、担当者登録前に運営がメールで渡さない）

### 4-4. 担当者が登録した時点の扱い

- 案A（推奨）: **本人に再確認してから届ける**。「◯◯社が OPINIO に参加しました。以前の『話を聞いてみたい』を届けますか？」（押してから時間が経つと状況が変わる・同意の対象が「担当者のいない会社への意思表示」から「匿名カードの提供」に変わるため）
- 案B: そのまま届ける（押した時点の同意で足りる前提。§6 の確認事項）
- どちらでも、押してから一定期間（例: 60日）を過ぎたものは届けない案

## 5. プライバシーポリシー・規約

### 5-1. 公開中の該当条文（引用）

**プライバシーポリシー 5-1（2026-10-18 版）**

> **当社は、次の場合に限り、求職者の個人情報を利用企業に提供します。**
>
> | 提供する場合 | 提供される情報 |
> |---|---|
> | **求職者が「転職について」で利用企業からの連絡を受け取る意思を示した場合** | プロフィール情報（**氏名を含み、連絡先を除く**）が、利用企業の管理画面（候補者の一覧および詳細）で閲覧可能になります。…表示される項目は、下記の別表のとおりです |
> | **求職者が求人に応募した場合** | 応募先の利用企業に対し、プロフィール情報および連絡先が提供されます |
> | **求職者が利用企業からのメッセージに返信した場合** | 当該利用企業に対し、連絡先が提供されます |

**求職者向け利用規約（2026-10-18 版）**

> 第3条2項 **当社は、ユーザーから、就職または転職のあっせんに関する手数料その他の金銭を一切受領しません**（職業安定法第32条の3第2項）。
>
