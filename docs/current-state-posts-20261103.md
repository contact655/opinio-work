# フェーズ0調査：企業の投稿と、フォロー相手だけのタイムライン（2026-11-03）

読み取りのみ。コード・データは変更していない。数字はすべて **2026-11-03 に本番 DB で実測**。

## 方針（調査の前提）

- 企業が会社として投稿できる（採用イベント、製品リリース、お知らせなど）
- 社員は今までどおり個人として投稿できる
- タイムラインには、フォローしている人と会社の投稿だけを出す。広告やフォロー外の投稿は差し込まない
- タイムラインが空のときは「フォローする会社を探す」だけを出し、フォロー外の投稿で埋めない
- 誰が誰をフォローしているかは、本人にしか見えない

## 用語

- **タイムライン** … `/feed`（ヘッダーの「フィード」）。ログイン後の着地の `/home`（「あなたの次の一手」）とは別の画面。
- **実ユーザー** … `is_test` でも `is_system` でもなく、本人が登録している（`auth_id` あり）利用者。
- **お知らせ** … OPINIO 名義のシステムユーザー（`00000000-…-0001`）が自動で作る投稿。

**投稿者が企業であることを表す仕組みは無い。**

- 投稿者は `user_id`（`ow_users`）だけで、企業を投稿者にする列が無い。
- 近いものは2つあるが、どちらも「企業が書いた」ことは表していない。
  - **`ref_company_id`**：投稿が**その企業についてのものである**という参照（お知らせが使う）。
  - **お知らせ**：投稿者はシステムユーザーで、企業ではない。

### 方針との差分

- 企業を投稿者として表す列（例: `author_company_id`）と、実際に押した担当者を残す列が要る。`user_id` が NOT NULL なので、どちらを持たせるかの設計が要る。
- 書き込みの権限（RLS）を「その企業で投稿してよい担当者」に絞る必要がある。今の `posts_insert_own` は本人の行しか見ていない。
- 見え方の判定 `isPostVisibleTo`（`lib/feed/visibility.ts`）は投稿者を人として扱っている（`private`・`is_test`・`is_system` を見る）。企業が投稿者の場合の規則（停止中・非公開・検証用の会社）が要る。
- 投稿カードの見出し（名前・アバター・現職）が人前提なので、企業の名前とロゴで出す形が要る。
- 企業管理画面（`/biz`）に、投稿を書く画面がまだ無い。

### 規模感：**大**

表の変更（列・権限・ビュー）、`/biz` の投稿画面と API、見え方の判定、フィード・パーマリンク・企業ページの投稿カードの描き分けを、まとめて変えることになる。

## 3. フォローのテーブルと見え方

### 現状（実測）

| 表 | 列 | 権限 |
|---|---|---|
| `ow_user_follows`（人をフォロー） | `follower_user_id`・`target_user_id`（一意・自分は不可） | RLS 有効。ポリシーは `user_follows_own_manage` 1本（**フォローした本人の行だけ**読み書き）。anon にも SELECT が付いているが、ポリシーで0件になる |
| `ow_company_follows`（**会社をフォローできる**） | `follower_user_id`・`company_id`（一意） | RLS 有効・**ポリシー0本**（クライアントからは誰も読めない） |
| ビュー `ow_follows_v` | 上の2つを合わせたもの | anon・authenticated とも権限なし |

会社のフォローは `POST/DELETE /api/jobseeker/companies/[id]/follow`、人のフォローは `/api/jobseeker/users/[id]/follow`。

**第三者に「誰が誰をフォローしているか」を返す経路は見つからなかった。** フォローの表を読む箇所はすべて、admin クライアントで「見ている本人が関わる行」だけを引いている。

| 場所 | 返すもの | 誰に見えるか |
|---|---|---|
| `/mypage/follows`（`mypage/follows/page.tsx:37`）・`/people?rel=following` | 自分がフォローしている相手 | 本人だけ |
| `/people?rel=followers`（`people/page.tsx:59`） | **自分をフォローしている人** | フォローされた本人 |
| 通知（`notifications/route.ts:134`。`type='follow'`） | **誰が自分をフォローしたか** | フォローされた本人 |
| プロフィール・検索・学校ページ・いいねした人の一覧 | 「あなたをフォローしています」（相手 → 自分の向き） | フォローされた本人 |
| 企業ページ・検索の「つながり」（`lib/companies/connections.ts:52-54`） | 相互にフォローしている人（相手の同意 `show_as_connection` が要る） | 相互の当事者 |
| ★フォロー数（`lib/people/followCounts.ts`） | **フォロワー数・フォロー中の数** | `/u/[id]`（`UserProfileContent.tsx:178`）を見る**誰にでも**。公開プロフィールなら未ログインにも |
| 企業側（`/biz`） | 会社のフォロワー一覧・人数とも**出していない**（企業側のコードにフォローの表を読む箇所が0件） | — |

### 方針との差分

- 第三者に関係（誰が誰を）を見せる経路は無いので、**大きな差分は無い**。
- 判断が要るのは2点。
  - **フォローされた側に見えているもの**（通知・フォロワーの絞り込み・「あなたをフォローしています」）。方針の「本人」に、フォローされた側も入るか。
  - **フォロー数が誰にでも見えること**。人数だけで相手は分からないが、方針の範囲に入るか。
- `ow_user_follows` に anon の SELECT が付いている。ポリシーで0件になるので漏れてはいないが、外しておくほうが意図が明確になる。

### 規模感：**小**

上の2点を「見せない」と決めた場合も、通知の文言・フォロワーの絞り込み・プロフィールの数字を外すだけで済む。

### 規模感：**小**

## 8. タイムラインをフォロー相手だけにしたとき、空になる人数

| | 実ユーザー 44人（エージェントの担当者を外すと 43人） |
|---|---|
| 誰も・どの会社もフォローしていない | **42人**（外すと 42人） |
| フォローしている相手に投稿が1件以上ある | **0人** |
| フォローしている会社に結び付く投稿（お知らせを含む）がある | **0人**（会社のフォローが0件） |
| ★**タイムラインが空になる** | **44人全員**（外しても 43人全員） |

- 実ユーザーが書いた投稿が0件で、会社のフォローも0件のため。
- お知らせを「会社の投稿」に含めても、会社をフォローしている実ユーザーがいないので結果は変わらない。
- 空でなくなる条件は、**実ユーザーが会社をフォローする**（その会社の投稿やお知らせが出る）か、**フォローしている人が投稿する**こと。
  - 参考：掲載中の会社22社のうち、結び付くお知らせ（掲載・募集）が1件以上あるのは **20社**。お知らせを含める場合、この20社のどれかをフォローすれば、少なくともそのお知らせは出る。残り2社は、フォローしても会社が投稿するまで空のまま。
