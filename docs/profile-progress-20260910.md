# プロフィールの進捗表示（`IntentCard` に組み込んだ）— 2026-09-10

登録直後の人が `/companies`（または元のページ）に着地するようになり
（`3048fa83` で完了画面を削除）、**自分がどこまで埋まっているかを知る機会が無くなった**のを受けた対応。

## 何を出すか — **4状態。%も「あと N 項目」も出さない**

判定は**2条件だけ**。0/50/100 を%で見せるのは**精度を装うだけで情報が増えない**
（思想⑦「マッチ度%・星評価を出さない」と同じ理由）。2条件しかないので
「あと1つ」「あと2つ」しか存在せず、**数える意味がない。**

| 状態 | 出すもの | 見た目 |
|---|---|---|
| ① `career_stance` **未設定** | **「いまは、企業の候補者検索に表示されていません」**＋「『転職について』に答えると表示され、企業から声がかかるようになります。」 | 琥珀（`--warm-soft` / `#FDE68A`） |
| ② `no_contact` | 「あなたの選択で、企業の候補者検索には表示されていません。」 | **灰色・枠なし** |
| ③ 答えている ＋ **職歴0件** | 「職歴を1件入れると、**その会社の企業ページに、あなたの名前が実名で表示されます**（見えるのは OPINIO にログインしている人だけです）。」 | 灰色・枠なし |
| ④ 2条件とも満たす | **何も出さない** | — |

⚠️★**①と②を同じ見た目にしないこと。** ①は「まだ答えていない」、②は「**答えた結果**」。
   混ぜると**本人の選択を不備のように見せる。** ②に警告色を使っていないのはそのため。
⚠️★**④で「完了！」を出さない。** 達成の演出は情報を増やさない。
⚠️★**①②と③を同時に出さない。** 一度に2つ言うとどちらを先にやればよいか分からなくなる。
   まず「表示される状態」にしてから職歴を促す（③は `isReachableByCompanies` が true のときだけ）。
⚠️ ③の公開範囲の言い回しは、**オンボーディングの h2 直下の一文と同じ文に揃えてある**。
   別の言い回しを増やすと、同じことを2通りで説明することになる。

## どこに出すか — `IntentCard` の中（**新規カードを作らない**）

`/mypage` は 2026-08-16 に「プロフィールの入口を1つにする」で整理した画面。
別カードを作ると**同じ設定への入口が2つ**になる（`.claude/rules/ui-debugging.md` ⑧の再発）。

⚠️ このカードの役割が「設定」から「**設定＋通知**」に広がる点は承知のうえ。
   **満たしている人には従来どおりの表示**（④で何も出さない）。

## 判定に使う条件 — 2つだけ

| 採った | 条件 | 理由 |
|---|---|---|
| ✅ | `career_stance` が非NULL かつ ≠`no_contact` | **スカウトと候補者検索の唯一の必須条件**。効果を1文で言える |
| ✅ | 職歴1件以上 | 企業ページの現役社員 / `/people` の中身 / 業界マッチが**すべてこれに乗る** |
| ❌ | 希望条件（求人おすすめ） | 「おすすめが良くなる」は**本人に検証できない**。約束が測れない |
| ❌ | `visibility` | 既定の `login_only` で十分。促すと**公開範囲を広げる方向に誘導**することになる |
| ❌ | 画像・自己紹介・肩書き | 効果を1文で言えない（「印象が良くなる」は根拠が出せない） |

### ★同じ述語が SQL と TS の2箇所に分かれている

判定は `lib/constants/careerPreferences.ts` の **`isReachableByCompanies()`** 1本にした。
中身は **`can_send_scout()`（SQL）の条件1と同じ**:

```
career_stance is not null and career_stance <> 'no_contact'
```

⚠️★**片方だけ変えると、画面が「届きます」と言っているのに届かない（またはその逆）になる。**
   `no_contact` の値を変える／条件を足すときは**両方を直すこと。**
⚠️ `can_send_scout()` の残りの条件（在籍企業・手動ブロック・勧奨禁止期間）は
   **相手企業ごとに変わる**ので、「自分がどの状態か」を本人に伝える用途では見ていない。
   **ここに足さないこと。**

### 職歴の件数は `experienceCount` で渡す

⚠️★**`currentCompanies` で代用しないこと。** あれは**在籍中かつ企業マスタに紐づく**会社だけで、
   自由入力の在籍先（実ユーザー11人中5人）や過去の職歴を数えない。
⚠️ `MypageClient` では `timelineCareers` を **destructure しない**（`...editorProps` に入ったまま
   `ProfileEditor` へ流れる必要がある）。`editorProps.timelineCareers?.length` で読む。
