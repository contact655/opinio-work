## 4. キャッシュの調査（実装していない）

### 4-1. いま何が起きているか

`/companies?industry=...` の絞り込み結果は **Next の fetch キャッシュ（Data Cache）に載る**。
`createPublicClient` は **意図して `no-store` にしていない**（ファイル冒頭に
「cookies() を呼ばないため Next.js の ISR/fetch キャッシュが有効になる」と明記）。

**実測（2026-09-04）**

| いつ | `?industry=collab` |
|---|---|
| migration 適用直後（本番・旧デプロイ） | **8社**（古い） |
| dev で `.next/cache/fetch-cache` を消した後 | **6社**（正しい） |
| 新しいデプロイ後（本番） | **6社**（正しい） |

### 4-2. ★書き換え経路に revalidate が1件も無い

| 経路 | `revalidatePath` / `revalidateTag` |
|---|---|
| `PUT /api/admin/companies/[id]/business-domains` | **0件** |
| `PUT /api/admin/companies/[id]/target-industries` | **0件** |
| `PUT /api/admin/companies/[id]`（企業情報） | **0件** |

→ **運営が `/admin` から事業領域を付け替えても、`/companies` の絞り込みは古いまま。**
   いまは「次のデプロイまで」直らない。

⚠️ `revalidateTag("business-domains")` を呼んでも**この問題は直らない。**
   タグが付いているのは `businessDomainsCached.ts` の2つ（選択肢と facet の件数）だけで、
   **`searchCompanies` の絞り込みクエリには付いていない。**

### 4-3. 影響範囲（`no-store` にする場合）

| | 実測 |
|---|---|
| `createPublicClient` を使うファイル | **8**（うち1つは `public.ts` 自身、1つは `/dev/preview`） |
| `createPublicClient()` の呼び出し | **22箇所** |
| `searchCompanies` / `getCompanies` の Supabase 問い合わせ | **9本**（うち4本は `unstable_cache` に包まれている） |
| `/companies?industry=collab` の応答（dev・warm） | **0.020〜0.029秒**（キャッシュが効いている状態） |

⚠️ **全体を `no-store` にすると、この 0.02秒 が毎回 Supabase への往復に変わる。**
   CLAUDE.md の実測では Supabase の1クエリが **60〜110ms**（東京同士）。
   **9本のうち直列の段数ぶんが毎リクエストに乗る。**

⚠️★**Disk IO の件を思い出すこと**（2026-08-23）。ビルドが本番 Supabase を叩きすぎて
   **Auth が40分落ちた**。問い合わせを増やす変更は、その予算を削る側に効く。

### 4-4. 案（2つ以上。実装していない）

#### 案A: 書き換え経路で `revalidatePath("/companies")` を呼ぶ（推奨）

- 触るのは admin の3ルートだけ。**日常の運用（/admin からの編集）はこれで直る**
- `revalidatePath` は**そのパスの Data Cache も落とす**ので、絞り込みクエリにも効く
- ⚠️ **migration で変えた場合は効かない**（`revalidatePath` 自体が走らない）。
  これは sitemap と同じ既知の穴で、**デプロイで直る**と割り切る
- ⚠️ `/companies/[id]` や `/jobs` にも波及するなら、そちらも一緒に呼ぶ判断が要る

#### 案B: 絞り込みクエリだけ `no-store` にする

- `searchCompanies` の**事業領域フィルタの1本だけ**を、`cache: "no-store"` を渡すクライアントで引く
- 増える往復は **1リクエストあたり1本**（`?industry=` が付いているときだけ）
- ⚠️ `createPublicClient` を全体で `no-store` にしない。22箇所すべてが毎回往復する

#### 案C: 短い `revalidate` を付ける（例: 60秒）

- `createPublicClient` の `global.fetch` で `next: { revalidate: 60 }` を渡す
- 常に最大60秒古い。**運営が編集した直後は反映されない**ので、案Aと組み合わせないと運用に合わない

#### 案D: 何もしない（現状維持）

- ⚠️ **いまは軸2も事業領域も日常的に編集しない**ので、実害は小さい
- ただし**「編集したのに画面が変わらない」を運営が踏む**。CLAUDE.md が繰り返し警告している形

**私の推し**: **案A**（運用で踏むのはこれ）＋ 必要なら**案B**（絞り込みだけ確実にする）。
案Cは単独では運用に合わない。

## 5. 実装フェーズへ持ち越す判断

1. **在籍中の企業を候補から除くか**（Opinio 社員に Opinio が出る）
2. **経験年数を出すなら年単位に丸める**（`started_at` は月精度・マージ必須）
3. **horizontal を混ぜない**（混ぜるなら別の見出しにする）
4. **IT出身者に同じ2社しか出せない状態で出すか**、企業を増やしてからにするか
