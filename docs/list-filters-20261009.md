## 1. 絞り込むと並び替えと件数が消えていた理由（/companies）

`companies/(list)/page.tsx` が、条件があるときだけ**別の部品**（`CompanySearchResults`）に切り替えていた。

- 並び替えのバー（`GridSortBar`）は `!hasFilter` のときだけ描かれていた
- `CompanySearchResults` は並び替えもページ分けも渡さずに `searchCompanies` を呼び、
  自前の「N社 が見つかりました」の見出しを出していた

つまり**絞り込み中は並び替えの指定が捨てられ**（URL に `?sort=` があっても効かない）、
件数は別の見出しで、別の場所に出ていた。⇒ 一覧グリッドと同じ経路に揃える。

## 3. 残り（今回は作らない）

### 会社規模の軸（従業員数の数値化の後）

`ow_companies.employee_count` は自由記述（「約200名」「51-200名」「1,000名以上」など）。
帯で絞るには数値が要る。

- 案（推奨）: **`employee_count_min` / `employee_count_max`（integer）を足し、企業ごとに入れる。**
  - 「約200名」→ 200 / 200、「51-200名」→ 51 / 200、「1,000名以上」→ 1000 / null
  - 機械変換の候補を出すスクリプトを作り、**運営が1社ずつ確かめて migration で入れる**（推測値を入れない）
  - 読めないものは NULL のまま（その企業は規模で絞ったときだけ落ちる）
- 帯は「〜50 / 51〜300 / 301〜1,000 / 1,001〜」など。帯をまたぐ幅を持つ企業は**重なる帯すべて**に入れる
- ⚠️ `parseEmployeeCount`（並び替え用）は文字列から1つの数を取るだけで、帯には使えない
