# フェーズ0：企業詳細「あなたとの共通点」（PR2）の調査（2026-11-28）

**柴さんの判断（2026-11-28）: PR2 は今回は作らない。** 調査結果をここに残す。
数字は 2026-11-28 時点の本番の実測。使う前に測り直すこと。

## 作ろうとしていたもの

ログインしている人にだけ、企業ページの「働く人」の先頭に小さなカードを出す。種類は2つだけ。

1. 同じ会社の出身：閲覧者の職歴（今の会社を含む）の会社と、その会社の現役社員の「この会社より前の職歴」の会社が同じ
2. 同じ職種：閲覧者の今の職種（無ければ直近）と、現役社員のこの会社での職種が同じ大分類（`ow_roles` の parent）

## データ

- 会社の突き合わせは `ow_experiences.company_id` でしかできない（`company_id` / `company_text` / `company_anonymized` の3つのうちちょうど1つ）。
  実在の利用者の職歴61件のうち company_id 49・company_text 12・anonymized 0。**自由入力の会社は対象外**（社名の文字列で突き合わせない）。
- 職種は `role_category_id`（主職種）。複数職種は `ow_experience_roles`（1職種だけの職歴には行が無い）。大分類は `coalesce(parent_id, id)`。
- `visibility_company`（real / masked / hidden）と `visibility_company_profile`（`/u/[id]` が見る列）は、2026-11-28 時点で全件 `real`。
- `ow_users.visibility`：実在の利用者53人＝public 11 / login_only 42 / private 0。

## 既存の関数で足りるか

- `getCompanyEmployees`（`src/lib/supabase/queries.ts`）は **この会社の行だけ**を返す。「同じ職種」はこの返り値（`roleParentId ?? roleCategoryId`）で足りる。
  **「同じ会社の出身」には新しい問い合わせが要る**（現役の userId について、この会社の最初の started_at より前の職歴。前職の行にも `visibility_company='real'`、`/u` に合わせるなら `visibility_company_profile='real'` も）。
- `getCompanyEmployees` の `isSeedRow` は `is_system` と統計利用の停止（`statistics_opt_out`）を見ていない。
- 社員一覧の API（`/api/jobseeker/companies/[id]/employees`）は閲覧者本人を一覧から外していない。
- 作りは「つながり」（`src/lib/companies/connections.ts` ＋ API ＋ `CompanyConnections.tsx`）と同じ形にする（ページ本体は ISR なので、閲覧者ごとの中身はブラウザから取る）。

## 実データ（2026-11-28）

- 在籍中の実在の社員がいる会社は22社。**8人の会社が1社、残り21社は1人ずつ**。
- 同じ前職を共有する現役社員は最大1人。
- 同じ大分類の職種の現役社員が5人以上そろうのは1社だけ。

## 規約から見た読み（判断は柴さん）

- 顔を添える以上、**統計（プライバシーポリシー4-3、利用規約第13条の4「個人を識別できない形式」）としては扱えない**。
  根拠になるのは、ログインしている人は「公開」と「ログインユーザーのみ」のプロフィールを見られるという条文（ポリシー5-2、利用規約第7条）。
- 気をつける点:
  1. **数字だけで人が決まる。** 21社は「1人」で本人が分かる。統計の下限（`MIN_AGGREGATE_COUNT = 5`）を当てると、「同じ会社の出身」は今どこにも出ず、「同じ職種」は1社だけ。
  2. **「つながり」は本人の同意（`ow_profiles.show_as_connection`、初期値オフ）を要する。** 共通点は同意なしで「あなたの前職の人がここにいる」という結びつきを作るので、つながりより踏み込む。規約にこの場面は書かれていない。
  3. 統計の利用を止めた人を顔と人数に出すかを決める必要がある（外すのが安全）。
  4. 閲覧者の現職が一致すると「あなたの今の会社の元社員がここにいる」を示すことになる（ただし `/u` で既に見える情報）。

## 再開するときに決めること

- 人数の下限（5人／3人／なし）
- 本人の同意を要するか
- 統計の利用を止めた人を外すか
- 閲覧者が検証用のとき、検証用どうしだけで出すか（「つながり」と同じ扱いにするか）
