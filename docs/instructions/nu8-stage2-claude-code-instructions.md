## §2. 前提と制約(必読)

### 2.1 段階1 で発覚した重要事項

#### 2.1.1 RLS 標準パターン(最重要)

opinio-work の RLS 標準パターンは `auth.uid() = user_id` ではない。**正しいパターン**:

```sql
CREATE POLICY "policy_name" ON table_name FOR <ACTION>
  USING (user_id IN (SELECT id FROM ow_users WHERE auth_id = auth.uid()));
```

`ow_users.auth_id` が Supabase Auth の uid を保持している設計。段階2 で新たに RLS を書く必要が生じた場合は、**必ず既存パターン(migration 079, 080 や類似テーブルの policy)を確認してから書く**こと。勝手に判断せず既存パターンに合わせる。

### 2.3 並行期間 UI の決定版

**仕様**:

- ある時期に複数の職歴(例: Salesforce 在籍中に Opinio 創業、本業 + 業務委託 等)が並行する場合、その時期のセクションは **縦に2列・3列に分割される**
- 並列の最大列数は **3列まで** サポート(4社以上並行は段階2 ではエッジケースとして1列ずつ縦に積む)
- 並列表示の対象は「期間が重なる職歴」であり、`is_current = true` が複数あるケースだけでなく、過去の重複期間も対象
- 並列されたカードは同じ高さ(min-height 揃え)、横に隙間を空けて配置
- 単独期間(並列なし)のセクションは従来通り全幅で1列
- ソート順: `end_year_month` が null(現職)を最上部 → その後 `start_year_month` の降順

**実装方針**:

- 職歴配列を「期間の重なりでグループ化」してから描画する
- グループ化アルゴリズム: ソート済み配列を頭から見て、既存グループの誰かと期間が重なれば同グループ、重ならなければ新グループ
- グループ内のカードを横並び(flex)、グループ自体を縦並び(flex-col)

**視覚イメージ**:

```
┌──────────────────────────────────┐
│ Opinio 株式会社  [現職バッジ]      │ ← 単独期間
│ 代表取締役 / 2年7ヶ月              │
└──────────────────────────────────┘
┌─────────────┬────────────────────┐
│ Salesforce  │ (業務委託 例)       │ ← 並行期間(縦2列)
│ 営業 / 6年  │ XX社 顧問 / 1年    │
└─────────────┴────────────────────┘
┌──────────────────────────────────┐
│ リクルート / 4年                  │ ← 単独期間
└──────────────────────────────────┘
```

### 5.1 グループ化アルゴリズムの正しさ
