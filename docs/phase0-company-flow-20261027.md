## 3. 表示の論点

### タブの並び

- いまは `?tab=` もパスの分岐も無く、**スクロール位置に追従するアンカーナビ**（`CompanyStickyNav`。`CompanyDetailClient.tsx:171,220-226`）。並びは 企業概要 → 社員・OB/OG（1人以上いるとき）→ 事業 → 募集 → 働く環境 → 記事（`CompanyDetailPage.tsx:1934-1943`）。
- 「人の流れ」を先頭に置くなら、新しいアンカーを足して並びを変えるだけで、**URL は変わらない**（`#人の流れ` 相当の id が増える）。

### 人数が少ない会社での出し方（いまの分布で考えた案）

| | 案 |
|---|---|
| 経歴由来 | 下限を **5人**（集計の下限と同じ）にすると、出せるのは Salesforce だけ。**3人**にしても同じく Salesforce だけ。1人から出すと「1人＝その人の経歴」になる |
| 回答由来 | 5人未満は項目ごと出さない（文言も出さない）。いまは全社で出ない |
| 全部出せない会社 | タブ（アンカー）ごと出さない。いまの「社員・OB/OG」（一覧）はそのまま残る |

### ログインしていない人に見せる範囲

- 社員・OB/OG の一覧は、未ログインには公開範囲が「公開」の人だけ（`employees/route.ts:40-47`）。「人の流れ」は集計なので、**数の内訳だけなら公開範囲に関係なく見せられる**が、少人数だと人が推測できる。ログインしている人だけに見せるか、未ログインにも見せるかは決める必要がある。

### 本人の勤務先の会社ページと、本人の数字

- 閲覧者の勤務先の数字を集計から外す仕組みは**無い**（`can_contact_without_stance` は企業に候補者を見せるかの判定で、企業ページの集計とは関係しない。`20261009070000_company_conversation_gate.sql:40-111`）。
- 集計に本人が含まれること自体は問題になりにくいが、人数が少ないと「自分以外の誰か」が逆算できる。下限（5人）で守るのが基本。

### キャッシュ

- 企業ページは `revalidate = 300`（`page.tsx:10`）、社員一覧は `unstable_cache`（300秒・タグなし）。編集時の即時反映は `revalidatePath`（`CompanyDetailPage.tsx:97-150`）。
- 集計も300秒で足りる（回答は少しずつしか増えない）。タグを付けるなら、職歴・回答の保存経路で `revalidateTag` を呼ぶ箇所が増える（いまはタグを使っていない）。

## 4. 既存の企業ページへの影響

- 「社員・OB/OG」（`CompanyEmployeeSections.tsx`）は、現役の一覧と職種の構成バー（3名以上・2職種以上）、OB の在籍期間と「現在：」を出している。「人の流れ」の在籍・行き先と**内容が重なる**（OB カードの在籍月数・現在の会社）。「人の流れ」は数の内訳、社員・OB/OG は1人ずつ、と役割を分けることになる。
- モバイル（1023px 以下）はサイドバーが消え、同じ部品（`CompanyInfoBox`）を本文の先頭に出している（`CompanyDetailPage.tsx:1966-1983`）。「人の流れ」を先頭に置く場合、モバイルでは企業情報の箱の下に来る。

2. 企業ページの社員一覧（`queries.ts:1830,1848`）と `buildMoves` の呼び出し元は、`hidden` だけを外し `masked` を通している。同じく**いまは0行**。

## Salesforce での表示サンプル（いまのデータ・個人名なし）

下限を5人にした場合（集計の基準どおり）:

```
人の流れ（10人の経歴から）
  在籍     平均 約4年4か月（OB 4人）            ← 4人なので出さない（下限5人）
  前職     メーカー 2・金融 2・不明 1            ← どれも5人未満なので出さない
  行き先   IT・インターネット 3・コンサル 1     ← 出さない
  社内の職種の変化  2人                         ← 出さない
  入社の決め手  2人                             ← 出さない
→ 結果として、セクションごと出ない
```

下限を3人にした場合（経歴由来だけ）:

```
人の流れ（10人の経歴から）
  在籍     OB の平均 約4年4か月（4人）
  前職     （業界の親でまとめても メーカー 2・金融 2 で、3人に届く行が無いので出ない）
  行き先   IT・インターネット 3人（業界の親でまとめた場合。会社名では1人ずつなので出ない）
  社内の職種の変化（2人）・入社の決め手（2人）は出ない
```

いまのデータでは、どちらの下限でもほとんど何も出ない。

## 柴さんが決める論点

1. **経歴由来の項目の下限**: 回答と同じ5人にそろえるか、3人にするか。1人から出すことはしない、でよいか。
2. **前職・行き先の粒度**: 会社名で出すか、業界（親）でまとめるか。会社名だと全行が1人になる。
3. **社内の職種の変化**: 子の職種で出すか（経路が見える）、親でまとめるか（いまは変化が0になる）。
4. **未ログインに見せるか**: 集計の数だけ見せるか、ログインした人だけにするか。
5. **出せない会社でのタブ**: アンカーごと出さない、でよいか。
6. **集計の作り方**: 案A（サーバーの関数で集計し、下限を落としてから数だけ渡す）でよいか。
7. **「話を聞ける社員・OB」**: 撤去済み。今回は入れない、でよいか。
8. **「社員・OB/OG」との重なり**: OB の在籍月数・「現在：」を、一覧に残すか「人の流れ」に寄せるか。
9. **masked を通している2か所**（`queries.ts` の一覧と「現在：」、`buildMoves` の呼び出し元）: いまは0行だが、直しておくか。

## 使った SQL（抜粋）

```sql
-- 母数（isAggregatableUser と同じ条件）
with pop as (
  select id from ow_users
  where auth_id is not null and is_test is not true and is_system is not true
    and coalesce(visibility,'') <> 'private' and statistics_opt_out = false
    and lower(coalesce(email,'')) not like '%@seed.internal')

-- 会社ごとの人数・前職・行き先（会社×人のまとまり＝stint。前職は開始前の最後の別会社の職歴、
-- 行き先は終了の1か月前以降に始まった最初の別会社の職歴）
, ex as (select e.* from ow_experiences e where e.user_id in (select id from pop))
, stint as (
  select user_id, company_id, min(started_at) s, bool_or(is_current) cur,
         case when bool_or(is_current) then null else max(coalesce(ended_at, started_at)) end e
  from ex where company_id is not null and visibility_company = 'real' group by user_id, company_id)
select ...  -- 本文の表を参照

-- 在籍月数（開始月と終了月を含め、重なりを除いて足す＝tenureMonths と同じ）
select user_id, count(distinct mon) months from (
  select e.user_id, generate_series(date_trunc('month', e.started_at),
    date_trunc('month', case when e.is_current then now() else coalesce(e.ended_at, e.started_at) end), interval '1 month') mon
  from ow_experiences e where ...) m group by user_id;

-- 回答（ow_career_turns は会社の列を持たないので職歴に結合する）
select e.company_id, count(*) filter (where cardinality(t.decisive_reasons) > 0) q1,
       count(*) filter (where t.fit_after_year is not null) q3
from ow_career_turns t join ow_experiences e on e.id = t.experience_id
where t.user_id in (select id from pop) and t.skipped_at is null group by 1;
```
