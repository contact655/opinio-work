## 実装前に柴さんが決めること（1a で出た論点）

1. **一人ずつ並べる一覧の件数（#16・#17）を統計として扱うか。** 企業カードの「現役社員 N名」や企業ページの「(N名)」「ログインすると N名のプロフィールが見られます」は、ログインすれば一人ずつ見られる人の数です。統計として扱うと、停止した人を数から外す（並んでいる人数と合わなくなる）うえ、5人未満は数を出せなくなります（いまはセールスフォースの現役6名以外すべて5人未満）。今回は**統計として扱っていません**。
2. **職種で企業を引くとき（#12）に下限を掛けるか。** 「この職種の人が1人でもいる会社」が当たる形です。下限を掛けると、職種で企業を探す検索はほぼ当たらなくなります。今回は停止した人と検証用を外すだけにしました。
3. **`current_member_count` / `obog_count`（#18）。** DB のトリガーが誰も除外せずに数えており、公開の `/api/companies/batch` が返しています（カードには出ていない）。列ごと使うのをやめるか、トリガーを直すか。
4. **担当者の既存の行（上の A〜C）。**
5. **プライバシーポリシー 5-1 の改定案**（[privacy-5-1-draft-20261026.md](privacy-5-1-draft-20261026.md)）の改定日と周知の方法。
6. 既にアカウントがある人を招待すると、相手はログインして承諾する必要があります。招待メールは未登録の人と同じ文面（`companyInviteTemplate`）です。文面を分けるかどうか。
