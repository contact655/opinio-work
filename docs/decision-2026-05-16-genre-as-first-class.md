# 思想決定: ジャンルを第一級属性とし、業界カラムを廃止する

**決定日**: 2026-05-16
**決定者**: Hisato（CEO）
**伴走**: Claude（戦略役）
**ステータス**: 思想確定、実装計画フェーズ

---

## 🎯 決定事項サマリー

`ow_companies.industry`（業界）カラムを廃止し、`ow_genres` × `ow_company_genres`（ジャンル）を企業の第一級分類軸として統一する。

---

## 📍 背景と問題の発見

### きっかけ

2026-05-16 朝のセッションで、`/companies` ページの 4列目カード途切れバグ（L6）の調査中に、Hisato さんから次の指摘:

> 外資系・ホリゾンタルSaaS・バーティカルSaaS
> 企業一覧の分類軸は企業詳細にデータが格納されていないのでは？

Claude Code による調査の結果、以下の3層欠落が判明:

1. **データ取得層**: `getCompanyById` が `ow_company_genres` を JOIN していない
2. **型定義層**: `Company` 型に `genres` フィールドがない
3. **UI 層**: 企業詳細サイドバー COMPANY INFO にジャンル行がない

加えて、本番企業（LayerX 等）の `ow_company_genres` 登録が未実施で、現時点ではテスト企業のみが一覧カルーセルに表示されている状態。

### より本質的な発見

調査の過程で、現状の `ow_companies.industry` カラムが既にジャンル的に運用されていることが判明:

- 一覧カードに「IT・300名」「SaaS・80名」「HRTech・300名」「FinTech・150名」と表示
- 「SaaS」「HRTech」「FinTech」はジャンル名と意味的に重複
- つまり「業界」と「ジャンル」の役割分担が不明確なまま運用されている

→ これは**整理すべき構造の歪み**であり、業界カラム廃止が正しい構造化の方向性。

---

## 🧭 確定した思想

### 思想1: ジャンルは「求職者目線の分類軸」

「業界」は企業の事業領域を表す客観的属性（単一値）。
「ジャンル」は **求職者がどんな切り口で企業を探すか** を表現する Opinio 独自の分類軸（複数値可能）。

Opinio が「キャリア意思決定インフラ」を名乗るなら、求職者目線の切り口こそが Opinio らしさの中核である。

### 思想2: 業界とジャンルの重複は構造の歪み

現状の運用（業界カラムをジャンル的に使う）は、構造として歪んでいる。ジャンルに統一することで、構造を本来あるべき形に整理する。

### 思想3: 一覧と詳細の認知経路を一致させる

求職者は一覧のジャンル別カルーセルから企業詳細に流入する。詳細ページの COMPANY INFO 最上部にジャンル表示があれば、流入経路と情報階層が一致し、認知負荷ゼロ。

### 思想4: 移行は段階的に、未登録企業は表示しない

ジャンル未登録企業は一覧にも詳細にも表示しない（ジャンル行ごと非表示）。「未設定」表示は UX を損なう。移行が完了した企業から順次表示される自然な段階移行とする。

### 思想5: ジャンル登録はセルフサーブの妨げにしない

企業作成オンボーディングでのジャンル選択は **任意**。Wantedly 型「誰でも企業新規作成可、即active化」の北極星に沿う。必須にすると登録ハードルが上がる。

## 📐 具体的な設計決定

### 表示設計

| 項目 | 決定内容 |
|------|----------|
| 表示位置 | 企業詳細 COMPANY INFO **最上部** |
| 並び順 | ジャンル → 事業ステージ → 従業員数 → 所在地 → 最寄り駅 |
| 複数所属時の見せ方 | **横並びチップ** |
| ジャンル未登録企業の扱い | **行ごと非表示**（自然な段階移行） |

### 入力設計（企業作成オンボーディング・編集画面）

| 項目 | 決定内容 |
|------|----------|
| 必須/任意 | **任意**（未選択でも企業作成可能） |
| 選択方式 | **複数選択可** |
| UI 形式 | **チップ群**（8ジャンル全部表示、タップで選択/解除） |
| 上限 | なし（自然な運用で落ち着く想定） |

### データ移行

| 項目 | 決定内容 |
|------|----------|
| 既存本番企業の industry → ジャンル変換 | **admin 手動マッピング**（自動マッピングは判断ミスのリスクが高い） |
| テスト企業データの industry 値 | 廃止時に削除 or 無効化（要設計） |
| migration 戦略 | Phase 2 の Claude Code 調査結果に基づき決定 |

## ⚠️ 留意事項

### 想定リスク

1. **想定外の industry 参照箇所**: 外部 API、統計、メール文面等で industry を使っている可能性。Phase 2 で洗い出し。
2. **本番企業の手動マッピング工数**: LayerX 等の本番企業数 × 1企業あたりの判断時間。Phase 2 で見積もり。
3. **段階リリース戦略**: industry カラムを一気に廃止するか、deprecated 期間を設けるか。Phase 3 で決定。

### 後日再考の可能性

本思想決定は「現状の運用を正しい構造に整理する」判断。後日、運用が進んで「業界とジャンルを併存させたほうが良い」と判断する可能性も残る。その場合は本文書を update。
