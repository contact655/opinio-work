# 「転職について」の入口が2つある理由（2026-09-11）

**`/onboarding` の2／3 と `/onboarding/stance` の両方が、同じ問いを出す。**
⚠️★**これは重複ではない。片方を消さないこと。**

## 実装は1つ

問いの文・「何が決まるか」の説明・4つの選択肢は
[components/onboarding/StanceQuestion.tsx](../src/components/onboarding/StanceQuestion.tsx)
にある。**両方がこれを描画している。** 二重定義ではない。

## 入口が2つ要る理由 —— 状況が違う

| 入口 | 誰のためか |
|---|---|
| `/onboarding` の **2／3** | **これから登録する人**。登録の途中で1問として聞く |
| **`/onboarding/stance`** | **過去に登録を終えたのに `career_stance` が空の人** |

後者へ送っているのは **`OnboardingGuard` の条件②**（遷移のたび）と
**`postAuth`**（ログイン直後）。どちらも**変更していない。**

### ②が拾う対象は1人（2026-09-11 / 本番・実ユーザー10人）

| | 人数 |
|---|---|
| `career_stance` が空 | 4 |
| **うちオンボーディング完了済み（＝②が拾う）** | **1** |
| うち未完了（①が拾う。新しい3画面を通る） | 3 |

⚠️ ②の対象は**これ以上増えない**見込み。`onboarding_completed` は登録の**最後**に立ち、
   その手前で必ず2／3 を通るため。**ただし0にはならない。**
   1画面目で「後で設定する」を押した人は `career_stance` が空のまま完了するので、
   **着地先で②が拾う。**（＝「答えていない人は必ず聞かれる」の最後の受け皿）

⚠️★**だから `/onboarding/stance` を消すと、その人たちが永久に聞かれなくなる。**
   `career_stance` はスカウトと候補者検索の唯一の必須条件なので、
   聞かれない＝本人にも企業にも何も起きない。

## 消す場合に必要なこと（採らなかった案）

`OnboardingGuard` と `postAuth` の行き先を `/onboarding?step=2` に変えることになるが、
**1問聞きたいだけの人を3画面の登録フローへ連れ戻す**ことになる。
戻るを押せば「1／3 直近のお勤め先」が出て、最後に「登録して始める」を押させる。
**重すぎるので採らなかった**（2026-09-11 / 柴さんの判断）。

## 2画面目だけ「次へ」が押せない

- `career_stance` を選ぶまで押せない。**スキップ（「後で設定する」）もこの画面だけ出さない**
  （出すと押せないようにした意味がその場で消える）
- **「答えない自由」は4つ目の選択肢（「今はいない」）が担保している**
- 押せない理由を必ずボタンの上に書く（「どれか1つ選ぶと、次へ進めます」）。
  ⚠️★灰色のボタンだけでは 1・3画面目の「未入力でも押せる灰色」と見分けが付かない
