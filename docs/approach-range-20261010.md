# 声かけを受け取る範囲（2026-10-10 / 声かけまわり 段2）

## 何をしたか

| | |
|---|---|
| 表 | `ow_approach_preferences`（範囲。`user_id` は ow_users）／ `ow_approach_blocked_companies`（受け取らない企業） |
| RLS | どちらも本人だけが読み書きできる（`auth_ow_user_id()`）。anon は GRANT なし |
| ★判定 | **DB 関数 `can_send_company_approach(company, candidate, sender)` の1か所**（SECURITY DEFINER・service_role だけ） |
| 中身 | `can_send_scout()` ＋ `accept_company_approaches = true` ＋ 受け取らない企業 ＋ 範囲（`company_in_approach_range()`）＋ 送る担当者と相手の is_test 一致 |
| 通る場所 | 送信 API の 403（`isApproachTarget`）／ 候補者検索のボタン（`approachTargets`）／ `/u/[id]` のボタン ／ 「声かけを受け取る方のみ」の絞り込み（ボタンと同じ値） |
| 承認するとき | **今のまま `can_send_scout()`**（届いた後で範囲を変えても承認できる） |
| 受け手の一覧 | 受け取らない企業に入れた会社からの承認待ちは**出さない**（`listIncomingApproaches`） |
| 画面 | `/mypage/settings` の「声かけを受け取る範囲」。下に「この範囲で声かけを送れる企業：N社」と注記 |
| 企業側 | `/biz` ホームの充実度の欄に「求人か職種を登録すると、声かけできる相手が増えます」（求人も職種も無い企業だけ） |
| 権限の検査 | `scripts/check-definer-grants.sh` が3本を「service_role だけが呼べる」で検査する（自己テスト付き） |
| migration | `20261010030000_approach_range.sql` |

## 範囲の決めごと

- **空の項目は「こだわらない」。** 行が無い人は全部こだわらない。
- **企業の値が未登録のとき、その項目で範囲を指定している人には届かない。** 範囲が空の人には届く。
- 職種: 「公開中の求人の職種」か「企業が登録した部門・職種のうち職種マスタに紐づいているもの」の**どちらか1つでも合えば合致**（柴さんの判断）。選べるのは IT/SaaS の大分類10件。大分類を選ぶと配下の職種にも合う。
- 業種: 大分類だけ選べる。大分類を選ぶと配下の業種にも合う。
- 会社規模: 段1の4つのまとまり（`COMPANY_SIZE_GROUPS`）。帯が未登録なら届かない。
- 勤務地: 本社の所在地か拠点（`branch_locations`）。
- リモート: 「リモートワークができる企業だけ」= `remote_work_status` が `full_remote` か `hybrid`。
- 件数（N社）: 公開中（`is_published`）・検証用でない・受け取らない企業でない・範囲に合う企業。**保存済みの範囲で数える。**

## 実測（2026-10-10）

- 範囲が空: 116社。規模 51〜500名 だけ: 44社。＋業種 IT・ソフトウェア: 41社。＋東京都: 38社（DB 関数と独立の計算が一致）。
- ⚠️★**職種の手がかりを持つ公開企業は1社だけ。** 職種を1つでも選ぶと、届く企業はほぼ0社になる。
  `/biz` ホームの一言はこのため。求人か職種を登録する企業が増えるまで、ここは狭いまま。

## 確かめたこと（陽性対照つき）

検証用の企業（ZAP）・担当者（contact+36）・求職者（contact+15）で、範囲と企業の値を切り替え、
**DB 関数・候補者検索のボタン・`/u/[id]` のボタン・送信 API の4つが全ケースで一致**することを確かめた。

| ケース | 結果 |
|---|---|
| 範囲なし・企業は未登録 | 届く（ボタンあり・API 200） |
| 規模を指定・企業の規模が未登録 | 届かない（ボタンなし・API 403） |
| 規模が合う／合わない | 届く／届かない |
| 規模が合う・受け取らない企業に入れた | 届かない |
| 業種が合う／合わない | 届く／届かない |
| 勤務地を指定・企業が未登録／合う | 届かない／届く |
| リモートのみ・企業が未登録／hybrid | 届かない／届く |
| 職種を指定・企業に求人も職種も無い | 届かない |
| 職種: 大分類を指定・企業が配下の職種を登録 | 届く。別の大分類・登録を削除済み → 届かない |

ほか: 受け取らない企業に追加 → 承認待ちが受け手の一覧から消え、解除で戻る ／ 設定 API の不正値は 400
（子の職種・`5001+`・`東京`・文字列の `remoteOk`）／ 未ログイン 401 ／ RLS は他人の行を読めず書けない ／
判定関数・件数関数をクライアントから直接呼ぶと 42501。検証データはすべて消した。

## 次に触る人へ

- ⚠️★**判定を TS に書き写さないこと。** 条件を足すなら `can_send_company_approach()`（と `company_in_approach_range()`）に足す。
- ⚠️ `companyHasApproachRoles()`（`lib/approaches/range.ts`）だけは表示のために職種の条件を TS に持っている。
  **DB 関数の職種の部分と同時に変えること。**
- ⚠️ 「ブロック中の企業」（`ow_scout_blocks`。候補者検索に出なくなる）と「受け取らない企業」（声かけだけ止める）は別。画面でも分けて説明している。
- ⚠️ 受け取らない企業の上限は50社（`MAX_APPROACH_BLOCKED_COMPANIES`。件数なので UI と API の2層）。
- ⚠️ 検証用の企業は、検証用の本人だけが受け取らない企業に入れられる。

## 追記：企業側のデータが揃っていない項目は出さない（2026-10-10 / 柴さんの指示）

| | |
|---|---|
| 切り替え | **項目ごとの有効フラグ**（`ow_approach_range_fields`）。⚠️ 割合で自動に切り替えない（企業1社の登録で範囲が急に変わるため） |
| 割合を見る場所 | **`/admin/approach-range`**（DB 関数 `approach_range_field_coverage()`）。50% を超えたら運営が「有効にする」を押す |
| 判定 | 無効の項目は `company_in_approach_range()` が見ない。**値が入っていても判定に使わない** |
| 画面 | 無効の項目は `/mypage/settings` に出さない。PUT で送られても保存済みの値を残す |
| 選択肢ごとの社数 | 「51〜500名（44社）」。**その選択肢だけを選んだとき**の社数（ほかの項目の選択は掛けない。掛けると、選ぶたびに他の選択肢が消えて選び直せなくなるため）。0社の選択肢は出さない（選択済みなら外せるように残す） |
| 狭いとき | 合計が10社未満で「範囲が狭く、声かけがほとんど届かない可能性があります」 |
| migration | `20261010040000`（フラグの表・項目ごとの判定関数・社数・割合）／ `20261010040100`（下記の不具合） |

割合（2026-10-10 / 公開中・検証用を除く116社）: 職種 1社（1%・無効）／業種 114社（98%・有効）／
会社規模 84社（72%・有効）／勤務地 84社（72%・有効）／リモート 2社（2%・無効）。
無効の項目に値を入れている人: 0人。

⚠️ 割合の分母は「公開中（`is_published`）」。合計の「N社」と同じ母集合（掲載中だけなら22社）。

⚠️★**項目ごとの「合うか」は `approach_company_matches_field()` の1か所。** 判定と社数が同じ関数を通る。
⚠️★`20261010040100` で直した不具合: リモートの判定が、未登録（null）の企業で null を返し、
   `not null` が null になって「合わない」で止まらなかった。**項目を一時的に有効にした陽性対照で発覚**
   （リモートは無効のままだったので、本番の判定には影響していない）。呼び出し側にも `coalesce` を入れて二重にした。

⚠️ `/biz` ホームの「求人か職種を登録すると、声かけできる相手が増えます」は、**職種の項目が有効なときだけ**出す
   （無効のあいだは登録しても届く相手は増えないため）。
